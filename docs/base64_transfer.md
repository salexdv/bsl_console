# Порционная передача Base64

Универсальный мост позволяет передавать из 1С большие двоичные данные без одной гигантской строки
в вызове JavaScript. Одновременно активна одна передача, а последний успешно собранный `Blob` хранится
до следующей успешной передачи или перезагрузки страницы.

```js
window.beginBase64Transfer(name);
window.pushBase64Chunk(chunk);
window.endBase64Transfer();
```

`name` — непустое диагностическое имя данных. `chunk` может быть как фрагментом одной общей
Base64-строки с произвольной границей, так и самостоятельным Base64-представлением бинарной порции.
Поэтому промежуточные порции из 1С могут заканчиваться padding `=` или `==`. Данные после padding внутри
одного `chunk` считаются ошибкой. Пробельные символы игнорируются.

Ошибочный порядок вызовов и повреждённый Base64 вызывают синхронное исключение;
предыдущий успешно подготовленный `Blob` при этом сохраняется.

Пример передачи HBK из клиентского кода 1С:

```bsl
Окно = Элементы.ПолеHTMLДокумента.Документ.defaultView;
Окно.beginBase64Transfer("shcntx");

Пока ЕстьЧасти Цикл
    Окно.pushBase64Chunk(ЧастьBase64);
КонецЦикла;

Окно.endBase64Transfer();
Окно.parseHelp();
```

Для `shlang_*.hbk` последовательность повторяется с именем `shlang`, включая отдельный вызов `parseHelp()`.
Ожидать Promise первого пакета не нужно: worker обработает оба запроса последовательно. `showHelp()` можно вызвать
сразу после запуска обеих загрузок.

Вызов `parseHelp()` без аргументов повторно использует последний подготовленный `Blob` и не удаляет его.

При чтении файла цикл должен уменьшать остаток на фактический размер буфера:

```bsl
ПереданоДанных = ПереданоДанных + РазмерБуфера;
РазмерДанных = РазмерДанных - РазмерБуфера;
РазмерБуфера = Мин(РазмерПорции, РазмерДанных);
```
