# Встроенный браузер справки 1С

Браузер принимает штатные файлы платформы `shcntx_*.hbk` (объектная модель) и `shlang_*.hbk`
(встроенный язык), `shquery_*.hbk` (язык запросов) и `dcsui_*.hbk` (система компоновки данных).
Файлы и построенные индексы живут только в текущей сессии страницы и не входят в сборку редактора.

## Загрузка

В обычном браузере HBK можно выбрать в компактной панели **Справка 1С** над редактором. Она скрыта
по умолчанию и показывается вызовом `window.showHelpLoader()`. Разрешён одновременный выбор нескольких
файлов; они загружаются последовательно, а результат каждого файла показывается в строке состояния.

```js
const result = await window.parseHelp(file);
// { ok: true, kind: "context", pages: 25503, error: null }
```

Аргумент может быть `Blob`, `File`, чистой Base64-строкой или Base64 data URL. Base64 декодируется
в worker и не блокирует основной поток страницы:

```js
const result = await window.parseHelp(base64);
```

Небольшую строку можно передать напрямую после загрузки HTML-документа:

```bsl
Окно = Элементы.ПолеHTMLДокумента.Документ.defaultView;
Окно.parseHelp(Base64Строка(Новый ДвоичныеДанные(ПутьКHBK)));
Окно.showHelp();
```

Большие HBK следует передавать порциями через универсальный
[`Base64-мост`](base64_transfer.md), после чего вызывать `parseHelp()` без аргументов.
Если загружаются оба пакета, `parseHelp()` нужно вызвать после завершения каждой из двух передач.
Проверка и декодирование порций выполняются в worker; ошибки данных возвращаются из соответствующего
`parseHelp()` обычным объектом результата.

Promise всегда разрешается объектом:

| Поле | Описание |
| --- | --- |
| `ok` | пакет полностью прочитан, дерево и индексы готовы |
| `kind` | `context`, `language`, `query`, `dcs` или `null` при ошибке |
| `pages` | количество проиндексированных HTML-страниц |
| `error` | текст ошибки или `null` |

Для большого `shcntx` сначала читаются оглавление и центральный каталог ZIP. После этого дерево,
предметный индекс и открытие отдельных статей уже доступны, а полная CRC-проверка и полнотекстовый
индекс достраиваются в отдельном index-worker. До публикации дерева HTML корневых разделов уже
прочитан, поэтому вместо `catalogNNN` показываются окончательные заголовки. При первом раскрытии
раздела его непосредственные дети приоритетно гидратируются; до ответа отображается индикатор загрузки.
Ответы и кэш относятся к поколению пакета, поэтому запоздавший ответ заменённого файла игнорируется.

Основной help-worker остаётся координатором и владельцем HBK. В production используется один
index-worker, который получает transferable-пакеты не более 512 КиБ или 128 ZIP-записей и выполняет
Deflate/Store, CRC, извлечение заголовков и построение поисковых документов. Если worker нельзя создать
или он аварийно завершился, кандидат автоматически повторяется в координаторе. `parseHelp()` по-прежнему завершается только после полной
проверки. Если поздняя проверка обнаруживает повреждение, новый кандидат отбрасывается, а предыдущий
успешно загруженный пакет восстанавливается вместе с раскрытием дерева, выбранной статьёй, историей и
прокруткой.

Сравнение eager, ленивой загрузки по оглавлению и штатного `IndexPackBlock` приведено в
[`specs/help-browser/benchmark.md`](../specs/help-browser/benchmark.md). На пакетах 8.3.25–8.5
ленивая загрузка по оглавлению дала в Chrome геометрическое среднее навигационной готовности 503,6 мс
вместо 3269,6 мс; поэтому она используется по умолчанию. Итоговое сравнение пула приведено в
[`benchmark-workers.md`](../specs/help-browser/benchmark-workers.md): один index-worker сократил
геометрическое среднее медиан полной готовности с 5785,1 до 4259,3 мс (1,36×). Два и три worker
отклонены из-за порога p95 ранней навигации.

Повторить замеры можно командами `npm run benchmark:help -- <hbk...>` и, после
`npm run build:headless`, `npm run benchmark:help:chrome -- <hbk...>`. Только конфигурации пула
проверяются командой `npm run benchmark:help:chrome -- --workers-only <большие-hbk...>`.

Пакеты можно передавать в любом порядке. Повторная успешная загрузка атомарно заменяет только пакет
того же вида. Если новый файл повреждён, прежняя успешно загруженная версия сохраняется. Состояния
разных режимов независимы: загрузка или ошибка `dcsui` не блокирует готовую BSL-справку.

Показываемый набор выбирается через [`setLanguageMode`](set_language_mode.md):

| Режим | Пакеты справки |
| --- | --- |
| `bsl`, `xml` | `shcntx` + `shlang` |
| `bsl_query` | только `shquery` |
| `dcs_query` | только `dcsui` |

## Открытие

```js
window.showHelp();
```

С необязательной строкой поиска функция повторяет логику `CTRL+F1`: панель открывается
на вкладке «Индекс», выполняется prefix-поиск по заголовкам и открывается первая найденная
статья:

```js
window.showHelp('Строка');
```

Как и `CTRL+F1`, вызов со строкой поиска работает только пока профильная справка текущего
режима полностью готова: в состояниях `empty`, `loading` и `error` панель не открывается
и запрос не откладывается. Без аргумента панель открывается всегда, показывая текущее
состояние справки.

Для показа скрытой по умолчанию панели ручного выбора `.hbk`:

```js
window.showHelpLoader();
```

Панель открывается сразу справа от Monaco, даже если профильный пакет ещё не загружен, и показывает
состояние справки текущего режима. Начальная ширина составляет 30%; внешний вертикальный разделитель меняет ширину панели.
Навигация расположена сверху, статья снизу, их высоту меняет внутренний горизонтальный разделитель.
Выбранные размеры и вкладка сохраняются между открытиями в текущей сессии. При смене языка открытая
панель остаётся видимой, но статья, история, поисковые строки и раскрытые узлы очищаются.

Кнопка **«Найти текущий элемент в дереве»** рядом с переходами «Назад»/«Вперёд» переключает панель
на вкладку «Содержание», раскрывает путь открытой статьи, выделяет её и прокручивает дерево до выбранной
строки. Дерево синхронизируется только по нажатию кнопки; обычные переходы по индексу, поиску и ссылкам
не раскрывают его автоматически. Пока статья не открыта или отсутствует в оглавлении активного пакета,
кнопка недоступна.

`CTRL+F1` в обычном редакторе и на активной стороне режима сравнения получает слово под курсором
через Monaco. Если профильная справка текущего режима полностью готова, действие открывает вкладку «Индекс» и
первую найденную статью; при отсутствии слова панель открывается без изменения вкладки и статьи.
Той же логике следует `window.showHelp('слово')` — явный вызов с переданной строкой поиска.
Во время загрузки, при ошибке или без HBK сочетание не открывает панель и не сохраняет отложенный
поиск. Опция [`generateGetHelpEvent`](set_option.md) позволяет независимо отправлять в 1С событие
[`EVENT_ON_GET_HELP`](get_help_event.md). Кнопка закрытия или `Esc` возвращает фокус в редактор и
восстанавливает его размер.

После успешной загрузки или замены `shcntx` редактор отправляет в 1С событие
[`EVENT_ON_HELP_READY`](help_ready_event.md). Загрузка `shlang`, `shquery`, `dcsui` и ошибки разбора
это событие не создают.

Вкладки панели:

* **Содержание** — ленивое дерево пакетов текущего режима;
* **Индекс** — регистронезависимый prefix-поиск по заголовкам; серым в скобках показывается компактный
  путь владельца, группы и статьи;
* **Поиск** — полнотекстовый AND-поиск, где `е` и `ё` эквивалентны.

Поиск показывает не более 1000 результатов, сохраняя полное число совпадений. Слова текущего запроса
подсвечиваются в открытой статье. Внутренние `v8help://` и относительные ссылки HBK открываются в той
же панели независимо от того, раскрыт ли целевой узел содержания. Якоря прокручивают статью к
указанному разделу, HTTP(S) открываются в отдельном безопасном окне.

В содержании пустые служебные разделы HBK отображаются как «Свойства», «Методы», «Конструкторы»,
«События», «Поля», «Параметры» или «Параметры формы», когда тип раздела однозначно определяется по
его непосредственным страницам.
