# Типизирующие комментарии

## Назначение

Редактор определяет тип переменной сам, разбирая код выше курсора: конструктор `Новый`,
присваивание другой переменной, результат метода или глобальной функции. Там, где вывести тип
нельзя — переменная приходит извне, заполняется функцией из общего модуля, является параметром
процедуры, — тип можно **объявить комментарием**.

Синтаксис совпадает со строгой типизацией 1С:Enterprise Development Tools, отдельного формата
учить не нужно.

## Формы записи

### Тип переменной

Комментарий вида `// ИмяПеременной - ИмяТипа` над кодом. Присваивание не обязательно — так можно
типизировать и параметр процедуры:

```bsl
// Таб - ТаблицаЗначений
Таб = ПолучитьТаблицу();

Таб.   // подсказка содержит методы таблицы значений
```

### Тип в конце строки присваивания

```bsl
Таб = ПолучитьТаблицу(); // ТаблицаЗначений

Таб.
```

### Тип с перечислением свойств

Для структуры имена ключей в справочнике не описаны — их задаёт код. Если структура приходит
извне, ключи можно перечислить:

```bsl
// Структура:
//  * Свойство1 - Строка
//  * Таблица - ТаблицаЗначений
Парам = ПолучитьПараметры();

Парам.           // Свойство1, Таблица и методы структуры
Парам.Таблица.   // методы таблицы значений: тип свойства учитывается дальше по цепочке
```

Блок привязывается к ближайшему присваиванию ниже. Пустые строки его не разрывают, строка кода —
разрывает.

## Как это сочетается с кодом

Объявленные имена — это **начальный** набор. Операции над коллекцией, выполненные ниже, меняют его
в обе стороны:

```bsl
// Структура:
//  * Ключ1 - Строка
//  * Ключ2 - Число
Пар = ПолучитьПараметры();
Пар.Удалить("Ключ2");
Пар.Вставить("Ключ3", 0);

Пар.   // Ключ1 и Ключ3; Ключ2 удалён и не предлагается
```

Так же набираются ключи структуры и колонки таблицы значений в обычном коде:

```bsl
ТЗ = Новый ТаблицаЗначений;
ТЗ.Колонки.Добавить("Код");
ТЗ.Колонки.Вставить(1, "Наименование");

Стр = ТЗ.Добавить();
Стр.   // методы строки плюс Код и Наименование
```

## Приоритет источников

Если про переменную известно из нескольких мест, побеждает более надёжный источник:

1. тип, полученный от 1С (через метаданные) или закреплённый выбором пункта подсказки;
2. типизирующий комментарий;
3. тип, выведенный из кода.

То есть комментарий переопределяет вывод из кода, но не спорит с типом, присланным 1С.

## Ограничения

* Имя типа должно быть известно редактору. Неизвестное игнорируется — подсказка ведёт себя так,
  будто комментария нет.
* Имена ключей и колонок распознаются только если записаны строковым литералом. Если на этом месте
  переменная или выражение, операция пропускается: набор окажется неполным, но неверные имена не
  появятся.
* Для соответствия ключи не предлагаются: к ним не обращаются через точку.
* Учитывается только код **выше** курсора.
* Ветвления не анализируются: если переменная получает разные типы в ветках `Если`, будет
  использовано последнее присваивание по тексту.
