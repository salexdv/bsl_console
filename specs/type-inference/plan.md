# type-inference: план реализации и решения

Транзиентный спутник [`spec.md`](spec.md).

## 1. План реализации

### Этап 1. Вывод типа из кода (текущий)

- Новый метод разбора: по имени переменной и позиции найти ближайшее присваивание выше и вернуть
  `{ref}` либо `null`. Формы — `Новый Х`, `V = W`, `V = Выражение.Метод()`, `V = ГлобальнаяФункция()`.
- Разрешение имени класса по справочнику `bslGlobals.classes` / `types` с учётом `name_en`.
- Разрешение метода: тип получателя → `bslGlobals.classes[Тип].methods[Метод].ref`.
- Фолбэк в `getRefCompletionFromPosition`: если `contextData` типа не дал — спросить слой вывода.
- Фикс `=` → `==` на `bsl_helper.js:1671`.
- Gate: критерии приёмки Этапа 1 из spec.md + зелёные `test:mocha` / `escheck` / `test:headless`.

### Этап 2. Типизирующие комментарии — сделано

- Разобраны три формы (spec.md §4.3); приоритет выше вывода из кода, ниже `contextData`.
- Объявленные свойства отдаются в подсказку напрямую и несут `ref` для работы по цепочке.
- Gate: критерии Этапа 2 закрыты, mocha 153/153. Полевая проверка на коде PrintWizard — за владельцем.

### Этап 3. Изменяемое состояние коллекций — сделано

- Набор ключей и колонок собирается по тексту с учётом снятия (`Удалить`/`Очистить`), см. spec.md §3.4.
- Операции ищутся по всему тексту сразу и применяются в порядке индексов, а не по строкам, — так
  несколько операций в одной строке отрабатывают правильно.
- Строка коллекции наследует колонки владельца.
- Gate: критерии Этапа 3 закрыты, mocha 163/163. Полевая проверка — за владельцем.

### Риски и снижение

- **Производительность.** Разбор идёт назад по тексту на каждой подсказке; на больших модулях это
  может стоить заметно (ср. #320, #335 — жалобы на тормоза на больших текстах). Снижение: искать
  только до начала процедуры/модуля, ограничить глубину рекурсии, кешировать по версии модели —
  как это уже сделано для объектной модели запроса.
- **Ложные типы.** Выведенный тип может оказаться неверным (переприсваивание в ветке `Если`,
  вызов по ссылке). Снижение: `contextData` всегда сильнее; при неоднозначности лучше не показать
  ничего, чем показать неверное.
- **Расползание в статический анализатор.** Держать границу из spec.md §6.

## 3. Решения

| Дата | Решение | Причина |
| --- | --- | --- |
| 2026-08-01 | Вывод типов делается слоем-фолбэком, а не заменой `contextData` | `contextData` несёт типы от 1С, которые точнее любого локального вывода |
| 2026-08-01 | Синтаксис типизирующих комментариев берём из строгой типизации ЕДТ | Разработчики 1С его уже знают; свой синтаксис никто учить не станет |
| 2026-08-01 | Трек разбит на 3 этапа, начинаем с вывода из кода | Этап 1 закрывает три из четырёх жалоб владельца и опирается на уже готовые `ref` в справочнике |
| 2026-08-01 | #336 (customObjects в запросах) ведётся отдельной спекой | Другой язык и другой путь подсказок; смешивать в один PR нельзя (правило CLAUDE.md) |
| 2026-08-02 | Вывод типа поднят выше эвристики `lookBehind` | Полевой дефект #305: догадка по соседнему `.метод(` выигрывала у разбора присваивания и подсказывала колонку вместо таблицы |
| 2026-08-02 | Резолвер цепочки носит `{ref, properties}`, а не голый ref | Иначе свойства из `// Структура:` не видны внутри цепочки `Парам.Таблица.` |
| 2026-08-02 | Соответствие исключено из сбора состояния | К ключам соответствия через точку не обращаются — только `Получить()` или `[...]`; подсказывать их после точки было бы враньём (замечание владельца) |
| 2026-08-02 | При сборе состояния строковые литералы НЕ маскируются | Имена ключей и колонок лежат именно в них; для поиска присваиваний маскирование остаётся |
