# type-inference: вывод типов переменных для подсказок встроенного языка

> Связанные issue: [#305](https://github.com/salexdv/bsl_console/issues/305) (контекстная подсказка
> для ТаблицаЗначений/ДеревоЗначений), [#295](https://github.com/salexdv/bsl_console/issues/295)
> (в подсказке отсутствуют методы объектов), [#228](https://github.com/salexdv/bsl_console/issues/228)
> (подсказка по свойствам структуры).

## 1. Контекст и проблема

Редактор **не выводит тип переменной из текста кода**. Подсказка «через точку» работает только
если тип переменной уже лежит в `window.contextData` — карте `номер строки → имя переменной →
{ref, parent_ref, sig}`. Наполняется она ровно двумя путями:

1. пользователь **выбрал** пункт подсказки мышью или Enter — тогда в неё кладётся
   `command.arguments[0].data` ([`bsl_helper.js:5087`](../../src/bsl_helper.js));
2. тип прислала 1С через метаданные/`EVENT_GET_DEFINITION`.

Набранный руками код типа не получает. Единственное исключение на весь файл — распознавание
`Новый Цвет(...)` для колор-пикера, к подсказкам отношения не имеющее.

Замер на собранном бандле (0.55.1, `contextData` пуст):

| Код | Подсказок после точки |
| --- | --- |
| `Таблица = Новый ТаблицаЗначений;` → `Таблица.` | **0** |
| `ТЗ = Таблица;` → `ТЗ.` | **0** |
| `Стр = Таблица.Добавить();` → `Стр.` | **0** |
| контроль: тот же `Таблица.` при заполненном `contextData` | 21, включая `ВыгрузитьКолонку` |

При этом данные для вывода **уже есть в справочнике**: `bslGlobals.classes.ТаблицаЗначений`
существует, а у методов проставлен тип результата —

```json
"Добавить": {
  "name": "Добавить",
  "returns": "Тип: СтрокаТаблицыЗначений. ",
  "ref": "types.СтрокаТаблицыЗначений"
}
```

Не хватает только звена, которое разберёт текст и наполнит `contextData` само. Симптом давно
известен и был описан в README как «подсказка через точку работает только тогда, когда реквизит
выбран через Enter», но чинился как частный случай, а не как отсутствие вывода типов.

Отдельно: строка `if (position.lineNumber = currentPosition.lineNumber)`
([`bsl_helper.js:1671`](../../src/bsl_helper.js)) содержит присваивание вместо сравнения — условие
всегда истинно и вдобавок мутирует `position`. Правится в рамках этой же задачи.

## 2. Область изменений

| Компонент | Тип | Характер изменений |
| --- | --- | --- |
| `src/bsl_helper.js` | src | новый слой вывода типов; фолбэк в `getRefCompletionFromPosition`; фикс `=`/`==` |
| `src/bslGlobals.js` | данные | точечные правки `ref`, если найдутся пропуски |
| `src/test.js` | тесты | кейсы вывода типов |
| `docs/` | доки | описание формата типизирующих комментариев (Этап 2) |

Публичный контракт моста **не меняется**: новые экспортные функции и события не вводятся,
существующие сигнатуры сохраняются. Меняется только полнота списка подсказок.

## 3. Поведение

### 3.1. Основной сценарий

Когда пользователь ставит точку после переменной и в `contextData` для неё типа нет, редактор
пытается вывести тип сам, разбирая текст **выше по документу** до текущей позиции.

Источники типа, по убыванию приоритета:

1. **`contextData` по имени переменной** — тип, полученный выбором подсказки или от 1С. Всегда
   сильнее выведенного: если 1С сказала тип, спорить с ней не надо.
2. **Типизирующий комментарий** — явное указание разработчика (§4.3).
3. **Вывод из кода** — последнее присваивание переменной выше текущей позиции.
4. **Эвристика `lookBehind`** — ищет выше ближайший `.метод(` и переиспользует его тип из
   `contextData`. Догадка по соседству, а не по имени переменной, поэтому она слабее всего
   перечисленного: именно её срабатывание давало #305 (после `А.Колонки.Добавить(...)` подсказка
   для `А.` показывала колонку вместо таблицы).

Вывод из кода покрывает формы:

| Форма присваивания | Выводимый тип |
| --- | --- |
| `V = Новый ИмяКласса;` / `V = Новый ИмяКласса(...);` | `classes.ИмяКласса` |
| `V = ДругаяПеременная;` | тип `ДругаяПеременная`, вычисленный рекурсивно |
| `V = Выражение.Метод(...);` | `ref` метода из справочника типа `Выражение` |
| `V = ГлобальнаяФункция(...);` | `ref` функции из `bslGlobals.globalfunctions` |

### 3.2. Граничные случаи

- **Русские и английские имена.** `Новый ТаблицаЗначений` и `New ValueTable` разрешаются одинаково;
  поле имени выбирается по `window.engLang`, как в остальном хелпере.
- **Переприсваивание.** Берётся ближайшее присваивание **выше** позиции курсора. Присваивания ниже
  игнорируются.
- **Цепочки и циклы.** Разрешение `V = W` рекурсивное, с ограничением глубины и защитой от цикла
  (`A = B; B = A;`) — при исчерпании лимита тип считается неизвестным.
- **Неизвестное имя.** Если класса/метода нет в справочнике, тип не выводится; подсказка ведёт себя
  как сейчас (пусто), ошибок не возникает.
- **Режимы запроса и СКД.** Слой работает только для языка `bsl`; в `bsl_query`/`dcs_query` не
  участвует.
- **Строки и комментарии.** Присваивание внутри строкового литерала или комментария источником типа
  не считается.

### 3.3. Ошибки

- Любой сбой разбора не должен ломать подсказку: слой обёрнут так, что при исключении подсказка
  формируется по-старому, а не пропадает.
- Вывод типа не отправляет запросов в 1С (`requestMetadata`) — только чтение локального справочника.

### 3.4. Изменяемое состояние коллекций

Для коллекций тип сам по себе неполон — нужны имена, которых в справочнике нет: колонки таблицы
значений, ключи структуры. Состояние набирается по тексту и **меняется в обе стороны**:

| Операция | Действие над набором имён |
| --- | --- |
| `Новый Структура("Ключ1, Ключ2")` | задать набор |
| `Структура.Вставить("Ключ", ...)` | добавить |
| `ТЗ.Колонки.Добавить("Имя", ...)` | добавить |
| `Структура.Удалить("Ключ")`, `ТЗ.Колонки.Удалить("Имя")` | убрать |
| `Структура.Очистить()`, `ТЗ.Колонки.Очистить()` | убрать все |

Порядок операций важен: набор имён на позиции курсора — результат применения всех операций **выше**
этой позиции по порядку. Удалённое после добавления в подсказке не показывается; вставленное
повторно после удаления — показывается.

Состояние собирается только для типов, к свойствам которых обращаются через точку: `Структура`,
`ФиксированнаяСтруктура` (ключи), `ТаблицаЗначений`, `ДеревоЗначений` (колонки). **Соответствие
сюда не входит** — к его ключам через точку не обращаются, только `Получить("Ключ")` или `[...]`.

Строка коллекции наследует её колонки: после `Стр = ТЗ.Добавить()` подсказка для `Стр.` содержит и
методы строки, и колонки таблицы.

Имена ключей и колонок живут в строковых литералах, поэтому при сборе состояния строки не
маскируются — в отличие от поиска присваиваний. Комментарии маскируются в обоих случаях.

## 4. Контракты

### 4.1. Экспортные функции моста

Не меняются. Новых функций не вводится.

### 4.2. События (`EVENT_*`) / формат обмена с 1С

Не меняются.

### 4.3. Типизирующие комментарии

Формат — подмножество строгой типизации ЕДТ, чтобы не изобретать свой синтаксис. Поддержаны три
формы; выигрывает последняя выше позиции курсора.

**Объявление типа переменной.** Работает и без присваивания — например, для параметра процедуры:

```bsl
// Таб - ТаблицаЗначений
Таб = ПолучитьТаблицу();
```

**Тип в конце строки присваивания:**

```bsl
Таб = ПолучитьТаблицу(); // ТаблицаЗначений
```

**Тип с перечислением свойств.** Имена свойств справочнику неизвестны, поэтому попадают в подсказку
как есть; указанный тип свойства работает дальше по цепочке (`Парам.Таблица.` даст методы таблицы):

```bsl
// Структура:
//    * Свойство1 - Строка
//    * Таблица - ТаблицаЗначений
Парам = ПолучитьПараметры();
```

Блок привязывается к ближайшему присваиванию ниже; пустые строки его не рвут, строка кода — рвёт.
Неизвестное имя типа игнорируется: подсказка ведёт себя так, будто комментария нет.

## 5. Критерии приёмки

Этап 1:

- [ ] `Таблица = Новый ТаблицаЗначений;` → `Таблица.` даёт методы таблицы значений.
- [ ] `ТЗ = Таблица;` → `ТЗ.` даёт то же, что `Таблица.`.
- [ ] `Стр = Таблица.Добавить();` → `Стр.` даёт методы строки таблицы значений.
- [ ] Английские имена (`New ValueTable`) разрешаются наравне с русскими.
- [ ] Тип из `contextData` не перекрывается выведенным.
- [ ] Циклическое присваивание не вешает редактор.
- [ ] `bsl_helper.js:1671` сравнивает, а не присваивает.
- [ ] Гейты зелёные: `npm run test:mocha`, `npm run escheck`, `npm run test:headless`.

Этап 2:

- [x] `// Таб - ТаблицаЗначений` типизирует переменную и без присваивания.
- [x] `Таб = ...; // ТаблицаЗначений` типизирует переменную.
- [x] Блок `// Структура:` добавляет объявленные свойства к штатным подсказкам типа.
- [x] Тип объявленного свойства работает по цепочке.
- [x] Комментарий сильнее вывода из кода, но слабее `contextData`.
- [x] Неизвестный тип в комментарии игнорируется; блок рвётся строкой кода.
- [x] Гейты зелёные: `npm run test:mocha`, `npm run escheck`, `npm run test:headless`.

Этап 3:

- [x] Ключи из `Новый Структура("Ключ1, Ключ2")` и из `Вставить` попадают в подсказку.
- [x] `Удалить` снимает имя, `Очистить` — все; повторная вставка возвращает.
- [x] Учитываются только операции выше курсора.
- [x] Колонки ТЗ добавляются и снимаются через `Колонки.Добавить` / `Удалить` / `Очистить`.
- [x] Строка таблицы наследует её колонки.
- [x] Ключи соответствия НЕ подсказываются.
- [x] Операция внутри строкового литерала не принимается за код.
- [x] Гейты зелёные: `npm run test:mocha`, `npm run escheck`, `npm run test:headless`.

## 6. Вне области

- Полноценный статический анализатор типов: областей видимости процедур, ветвлений, объединения
  типов по веткам `Если` здесь нет.
- Типы параметров процедур и функций по описанию в шапке — отдельная задача.
- Режим запроса: `customObjects` для временных таблиц ([#336](https://github.com/salexdv/bsl_console/issues/336))
  ведётся отдельной спекой.
- Изменения публичного контракта моста и событий.
