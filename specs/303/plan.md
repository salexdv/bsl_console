# 303: план реализации и решения

## 1. План реализации

1. Добавить чистую MRU-модель и защитный адаптер к find-контроллеру Monaco.
2. Добавить меню истории и публичные функции моста.
3. Покрыть модель модульными тестами, мост и UI — headless-смоуком.
4. Выполнить обычную, production и single-file проверки.

### Риски и снижение

- Find-история не входит в публичный API Monaco. Все приватные поля проверяются перед использованием,
  а их имена сосредоточены в одном модуле.
- В Monaco 0.20 нет публичной замены истории: адаптер вызывает приватный lifecycle существующего
  `HistoryNavigator`, не подменяя сам виджет и не затрагивая историю строки замены.
- Find-виджет создаётся лениво. Адаптер подписывается на состояние контроллера и подключает UI только
  после фактического создания виджета.

## 3. Решения

| Дата | Решение | Причина |
| --- | --- | --- |
| 2026-08-03 | Внешний формат — JSON-массив от новой строки к старой | Удобен для 1С и совпадает с порядком меню |
| 2026-08-03 | Встроенное добавление истории отключается только у поля поиска | Не менять штатную историю замены |
| 2026-08-03 | Постоянное хранение остаётся на стороне 1С | Standalone storage Monaco работает только в памяти документа |
| 2026-08-03 | Подтверждение `Enter` фиксирует строку наравне с потерей фокуса | Кнопка истории должна становиться доступной сразу после обычного поиска |
