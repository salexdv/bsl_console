# help-browser: встроенный браузер синтакс-помощника 1С

## 1. Контекст и проблема

Редактор не умеет принимать штатные `shcntx_*.hbk` и `shlang_*.hbk` платформы и показывать их без
распаковки на диск. Функция добавляет сессионную справку справа от Monaco, пригодную для обычного,
query- и diff-режимов и для single-file поставки в старом WebKit поля HTML-документа 1С.

## 2. Область изменений

| Компонент | Тип | Характер изменений |
| --- | --- | --- |
| `src/help/` | src | reader контейнера/ZIP, TOC, worker, service, UI и CSS |
| `src/editor.js` | src | публикация API, Ctrl+F1, синхронизация темы |
| `tests/`, `tools/` | тесты | unit и browser/headless проверки |
| `README.md`, `docs/` | доки | API и клавиша |

## 3. Поведение

### 3.1. Загрузка

`parseHelp(source)` принимает `Blob`/`File`, чистую Base64-строку или Base64 data URL, распознаёт
context (`shcntx`) или language (`shlang`),
в worker читает FileStorage/PackBlock, строит навигацию, индекс имён и полнотекстовый индекс. Два
вида пакетов объединяются в одной сессии. Успешная повторная загрузка атомарно заменяет только свой
вид; ошибка не изменяет ранее готовый пакет. Promise завершается после построения всех индексов.

Production-reader использует стратегию `toc-lazy`: после структурной проверки HBK, `PackBlock` и
центрального каталога `FileStorage` пакет публикуется как предварительный. Статьи проверяются при
открытии, а полный проход CRC и полнотекстовый индекс выполняются пакетами в index-worker; локальный
fallback уступает очередь каждые 12 мс. До его окончания
поиск ожидает готовности. Поздняя ошибка откатывает предварительный пакет к предыдущему подтверждённому.
Стратегии `eager-html` и `native-index-lazy` остаются только в benchmark-entry и не входят в production.

Перед предварительной публикацией распаковываются HTML корневых узлов TOC. Заголовок выбирается в
порядке: русское имя TOC, HTML-заголовок, английское имя TOC, вычисленное системное имя, имя файла.
Непосредственные дети гидратируются при раскрытии уровня; до ответа worker вместо системных имён
показывается индикатор. Уровни кэшируются по поколению пакета, ответы старых поколений игнорируются.

Полную проверку и индексирование выполняет один верхнеуровневый index-worker, выбранный фактическим
Chrome benchmark. Координатор передаёт ему сжатые ZIP-записи transferable-пакетами до 512 КиБ или
128 записей, не более одного пакета одновременно. Worker выполняет Store/Deflate, CRC/размеры,
извлечение заголовков и построение документов. Корпуса подтверждённого пакета и кандидата разделены;
ошибка отменяет кандидат. Ошибка создания или авария worker переводит текущий кандидат на локальную
индексацию в координаторе без изменения публичного контракта.

Для больших данных универсальные `beginBase64Transfer(name)`, `pushBase64Chunk(chunk)` и
`endBase64Transfer()` инкрементально собирают один сессионный Blob в worker. Основной поток только
проверяет типы и порядок вызовов и передаёт порции worker без просмотра и декодирования их содержимого.
`pushBase64Chunk` принимает как фрагменты одной Base64-строки, так и отдельно закодированные бинарные
порции с padding. `parseHelp()` без аргументов ставится после порций в ту же FIFO-очередь и использует
результат последней завершённой попытки; незавершённая передача и отсутствие попытки возвращают обычный
неуспешный `HelpParseResult`.

Пустое имя, нестроковый `chunk` и неверный порядок вызовов создают синхронное исключение. Ошибки
содержимого Base64, пустая передача и неполная последняя группа определяются worker и возвращаются из
`parseHelp()` как неуспешный `HelpParseResult`. Ошибка завершённой попытки повторяется до следующего
`beginBase64Transfer`; ранее загруженный пакет справки при этом не изменяется.

Для двух HBK `parseHelp()` вызывается сразу после `endBase64Transfer()` каждого файла. Ожидать
Promise первого пакета не нужно, так как worker имеет последовательную очередь разбора.

### 3.2. Просмотр

`showHelp()` немедленно открывает закреплённую справа панель, не перекрывая Monaco. Начальная ширина —
30%, минимум панели — 340 px, минимум редактора — 300 px. В верхней секции находятся вкладки
«Содержание», «Индекс», «Поиск», в нижней — статья. Вертикальный внешний и горизонтальный внутренний
разделители меняют ширину панели и соотношение секций; начальное соотношение равно 45/55.
Панель содержит ленивое дерево, виртуальные списки, историю статьи и закрывается кнопкой/Esc.
Вкладка, статья и оба размера сохраняются между открытиями; после изменения размеров и закрытия
выполняется layout редактора, а фокус возвращается в Monaco.

Верхняя компактная панель `index.html` по умолчанию скрыта. `showHelpLoader()` показывает её для
ручной проверки в браузере. Панель позволяет выбрать один или несколько `.hbk`, последовательно
передать каждый `File` в `parseHelp` и открыть браузер справки. Она показывает текущий файл и итог
каждой загрузки, не перекрывая Monaco.

### 3.3. Поиск и безопасность

Индекс имён ищет префикс без регистра только по основному имени. Для каждой строки дополнительно
показывается серый компактный контекст `владелец/группа/имя`, полный текст которого доступен в tooltip.
Пустые служебные узлы TOC восстанавливаются как «Свойства», «Методы», «Конструкторы», «События»,
«Поля», «Параметры» или «Параметры формы» только при однозначном типе непосредственных страниц.
Полнотекстовый поиск требует все слова, считает `е` и `ё`
эквивалентными, ранжирует заголовок выше текста, возвращает `total` и не более 1000 строк. В статье
подсвечиваются слова активного запроса.

HTML разбирается через `DOMParser`: удаляются исполняемые/встраиваемые элементы, формы, inline-
обработчики и опасные URL. `SyntaxHelperContext`/`SyntaxHelperLanguage`, относительные пути и якоря
становятся внутренними переходами; пути разрешаются относительно текущей статьи без зависимости от
раскрытия TOC. HTTP(S) открываются отдельно с `noopener,noreferrer`.

### 3.4. Ошибки формата

Reader принимает Store/Deflate, префикс и хвост HBK; проверяет сигнатуры, границы, размеры и CRC.
Таблица сущностей учитывает отсутствующий адрес `2147483647`; многочастные сущности собираются по
цепочкам 31-байтовых заголовков, а одноблочные читаются без копирования.
Zip64, шифрование, data descriptor без проверяемых размеров, повреждения и неизвестный пакет
отклоняются с диагностикой.

## 4. Контракты

```js
/** @param {Blob|File|string} source @returns {Promise<{ok:boolean,kind:string|null,pages:number,error:string|null}>} */
window.parseHelp = function (source) {};

window.beginBase64Transfer = function (name) {};
window.pushBase64Chunk = function (chunk) {};
window.endBase64Transfer = function () {};

/** @returns {void} */
window.showHelp = function () {};
window.showHelpLoader = function () {};
```

`kind` равен `context`, `language` либо `null`. Функция всегда разрешает Promise объектом результата
и не отклоняет его наружу. После каждого успешного результата `context` вызывается
`window.sendEvent('EVENT_ON_HELP_READY')` без параметров; `language` и ошибки событие не создают.
Порционные функции сохраняют синхронную сигнатуру `void`; ожидать их Promise из 1С не требуется.

Monaco action `bsl.showHelp` имеет сочетание `monaco.KeyMod.CtrlCmd | monaco.KeyCode.F1`. При наличии
слова `model.getWordAtPosition(position)` и готовой справки действие открывает вкладку «Индекс»,
выполняет prefix-поиск и открывает первый результат; без слова выполняется обычный `showHelp()`.
В состояниях `empty`, `loading` и `error` панель не открывается, запрос не откладывается. Опция
`generateGetHelpEvent` отправляет `EVENT_ON_GET_HELP` с тем же контекстом, что `EVENT_GET_DEFINITION`,
если под курсором есть слово; событие не зависит от готовности HBK. Обычный F1 не меняется.

Worker и стили входят в обычный и single-file bundle; внешних файлов и реальных HBK в поставке нет.
Для Deflate используется browser/inflate-сборка pako. Код основного бандла и каждого извлечённого
Blob-worker сохраняет ES2018 floor и избегает синтаксиса, неподдерживаемого старым WebKit.

## 5. Критерии приёмки

- [x] Оба HBK загружаются в любом порядке, объединяются и заменяются атомарно.
- [x] Содержание, индекс, поиск, статья, внутренние ссылки и история работают.
- [x] Панель закреплена справа; навигация расположена над статьёй, оба разделителя сохраняют размеры.
- [x] Индекс показывает компактный контекст, а системные группы TOC восстановлены без ложных переименований.
- [x] Статья открывается по page id с обязательным fallback по `kind + path`.
- [x] Ctrl+F1 ищет слово и открывает первый результат в обычном/query/diff режимах; Esc возвращает фокус и layout.
- [x] Без готовой справки Ctrl+F1 не открывает панель; `generateGetHelpEvent` независимо создаёт `EVENT_ON_GET_HELP`.
- [x] Относительные ссылки и якоря статей разрешаются безопасно без предварительного раскрытия TOC.
- [x] Успешный `shcntx` создаёт `EVENT_ON_HELP_READY` без параметров; `shlang` и ошибки — нет.
- [x] ZIP/TOC/service/search покрыты unit-тестами, UI — headless-тестом.
- [x] На стадии prepared корни имеют окончательные заголовки, а раскрытие не показывает `catalogNNN`.
- [x] Пакетирование, CRC, поколения, отмена, ответы вне порядка и fallback index-worker покрыты тестами.
- [x] Реальный `shcntx_ru.hbk` даёт ориентиры 52 048 записей, 25 503 HTML, 28 352 TOC-узла.
- [x] Отдельно закодированные порции по 1 МБ с padding собирают реальные HBK без изменения байтов.
- [x] Проверка и декодирование Base64-порций выполняются в worker; UI-поток остаётся отзывчивым.
- [x] Все application/javascript Blob-worker проходят отдельную ES2018-проверку.
- [x] Выполнены HBK unit/browser/headless, реальные smoke и benchmark, `build`, `build:single`, `escheck` и проверка Blob-worker.
- [ ] Общий `npm test` не зелёный из-за существующих сбоев query corpus и прямого `worker-loader` require в `query-model-service`.

## 6. Вне области

- Сохранение HBK между сессиями и поставка файлов справки.
- Перехват обычного F1.
