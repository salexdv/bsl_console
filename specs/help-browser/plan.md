# help-browser: план реализации и решения

## 1. План реализации

1. [x] Вертикальный срез: строгий HBK/ZIP reader, TOC/language navigation, blob-worker и сессионный service.
2. [x] Overlay UI, sanitization, виртуализация, поиск, история и интеграция API/action/theme в `editor.js`.
3. [x] Синтетические unit-тесты форматов/сервиса/поиска и browser/headless сценарии.
4. [x] Реальные smoke, документация и финальные сборочные гейты.
5. [x] Прямой приём чистого Base64/data URL из моста 1С с декодированием в worker.
6. [x] Универсальная порционная Base64-передача и `parseHelp()` без аргументов.
7. [x] Ручная загрузка одного или двух HBK через компактную панель над Monaco.
8. [x] Перестройка overlay в закреплённую правую панель с вертикальной компоновкой и двумя разделителями.
9. [x] Семантические группы TOC, контекст индекса и надёжное разрешение статьи по page id/path.
10. [x] Совместимый с WebKit pako inflate, порции Base64 с промежуточным padding и ES-гейт Blob-worker.
11. [x] Скрытие ручного загрузчика HBK по умолчанию и публичный `showHelpLoader()`.
12. [x] Поиск слова под курсором по Ctrl+F1 и событие `EVENT_ON_HELP_READY` для готового `shcntx`.
13. [x] Безопасные относительные ссылки/якоря и опциональное событие `EVENT_ON_GET_HELP` без открытия неготовой справки.
14. [x] FIFO-передача Base64-порций в worker без изменения последовательности вызовов из 1С.
15. [x] Альтернативные eager/TOC/native-index стратегии и воспроизводимые Node/Chrome замеры.
16. [x] Предварительная готовность TOC, фоновая CRC/полнотекстовая индексация и откат кандидата.

### Риски и снижение

- FileStorage в версиях платформы может быть разбит: context читается из адресованной сущности,
  language — строгим сканированием валидных local records всего контейнера с CRC.
- Десятки тысяч страниц: HTML остаётся в worker, списки виртуализированы, основному потоку передаются
  только навигация, краткие результаты и выбранная статья.
- Старый WebKit: worker собирается существующими blob/compile loaders, исходники транспилируются Babel.

## 3. Решения

| Дата | Решение | Причина |
| --- | --- | --- |
| 2026-08-10 | Хранить два независимых поколения пакетов в worker | Атомарная замена одного вида без потери второго |
| 2026-08-10 | Для shlang проверять local ZIP records во всём HBK | Реальный FileStorage может быть физически разбит между блоками |
| 2026-08-10 | Полнотекстовый индекс хранить как нормализованный текст документа | Простая AND-семантика, точный total и приемлемый объём для ~25 тыс. статей |
| 2026-08-11 | Закрепить справку справа с начальной шириной 30% | Код и статья остаются одновременно видимыми, как в синтакс-помощнике 1С |
| 2026-08-11 | Выводить навигацию над статьёй в соотношении 45/55 | Уточнения в дереве/индексе и выбранная статья видны в одной узкой панели |
| 2026-08-11 | Отделить TOC id от page id и всегда оставлять fallback `kind + path` | Числовой id оглавления не совпадает с ключом HTML-страницы |
| 2026-08-11 | Восстанавливать пустые группы только по единственному сегменту непосредственных страниц | Исправляет «Без названия», не давая ложных имён смешанным узлам |
| 2026-08-11 | Импортировать `pako/browser/inflate` и проверять синтаксис всех Blob-worker | Обычный `escheck` не видит JS, хранящийся строкой внутри бандла |
| 2026-08-11 | Разрешить padding между отдельными вызовами `pushBase64Chunk` | 1С кодирует каждую бинарную порцию Base64 независимо |
| 2026-08-11 | Ctrl+F1 открывает первый prefix-результат активного редактора | Повторяет привычный переход из редактора в синтакс-помощник 1С |
| 2026-08-11 | `EVENT_ON_HELP_READY` отправляется без параметров после каждого успешного `shcntx` | 1С получает однозначный сигнал полной готовности контекстной справки |
| 2026-08-11 | Ctrl+F1 открывает панель только при `service.status === ready` | Неготовая справка не меняет интерфейс и не создаёт отложенный переход |
| 2026-08-11 | `generateGetHelpEvent` независимо отправляет полный контекст слова | 1С может обработать запрос справки даже без загруженных HBK |
| 2026-08-11 | Относительные ссылки разрешаются от пути текущей статьи | Обзорные страницы работают без раскрытия соответствующего узла TOC |
| 2026-08-12 | Проверять и декодировать порции Base64 в существующем worker справки | `pushBase64Chunk` не выполняет линейную работу на UI-потоке, а код вызова из 1С не меняется |
| 2026-08-12 | Возвращать ошибки содержимого порций через `parseHelp()` | Асинхронный worker не может безопасно выбросить исключение в завершившийся вызов `pushBase64Chunk` |
| 2026-08-16 | Использовать `toc-lazy` в production | Chrome: навигация в среднем 457,5 мс против 2970,9 мс eager (6,49×); p95 полной готовности укладывается в допуск +20% |
| 2026-08-16 | Не включать native-index parser в production | Штатный двуязычный индекс полезен, но увеличивает навигационную готовность примерно вдвое относительно TOC |
