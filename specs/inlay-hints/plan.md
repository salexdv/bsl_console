# inlay-hints: план реализации и решения

Транзиентный спутник [`spec.md`](spec.md). Живёт до закрытия задачи; после merge либо удаляется,
либо уезжает в `specs/done/inlay-hints/plan.md` как архив развития.

## 1. План реализации

### Этап 1. Контроллер `src/inlay_hints.js`

- Шаги: `createInlayHintsController(codeEditor)` по образцу `createInlineGhosttextRenderer`
  (`src/editor.js`): декорации `afterContentClassName` + один `<style>` на редактор с правилами
  `content` для уникального класса каждого хинта; парсинг/валидация входа (JSON-строка или массив);
  экранирование CSS-строки; `getState()` для тестов.
- Gate: контроллер вручную проверяется в консоли DevTools на `npm run debug`.
- Оценка: один файл ~200 строк.

### Этап 2. Интеграция `src/editor.js`

- Шаги: контроллер в `initEditorEventListenersAndProperies`; `window.setInlayHints` /
  `window.clearInlayHints` (рядом с `enableInlineSuggestions`); ветка `showInlayHints` в
  `setOption`; клик в существующем `onMouseDown` (по образцу `diff-navi`).
- Gate: мост живой — функции на `window`, события доходят до `events_queue`.

### Этап 3. Стили и документация

- Шаги: базовый класс `bsl-inlay-hint` в `decorations.css` (цвет через `.vs`/`.vs-dark`,
  без JS-перекраски); `docs/inlay_hints.md`; строка в `docs/set_option.md`; README.
- Gate: доки в тон существующих (по образцу `show_inline_suggestion.md`).

### Этап 4. Тесты и гейты

- Шаги: `describe` в `src/test.js` (установка/очистка/toggle/экранирование/невалидный вход/
  позиции вне модели/клик через подмену `editor.sendEvent`); прогоны `test`, `build:test` +
  `test:mocha`, `escheck`, `build`, `test:headless`.
- Gate: все гейты зелёные; мост на `window` проверен после сборки.

### Риски и снижение

- Клик по `::after`: event target — span с классом декорации (псевдоэлемент не бывает таргетом);
  проверяется в headless Chrome. Fallback — поиск хинта по позиции клика.
- Экранирование CSS `content` — главный источник багов; покрыто тестами (кавычки, слэши,
  управляющие символы).
- Старый WebKit поля 1С: `::after` внутри текста Monaco уже используется ghost-текстом — риск
  низкий; `pointer-events` на псевдоэлементе проверяется вручную в поле 1С на 8.3.14+.
- Уникальность CSS-классов между редакторами (вкладки) — префикс с uid контроллера.

## 2. Открытые вопросы

- Требуется ручная проверка в поле 1С (8.3.14 и 8.3.27+) — за мейнтейнером.
- Следующий этап (автотипы у присваиваний через слой `specs/type-inference`) — отдельная спека.

## 3. Решения

| Дата | Решение | Причина |
| --- | --- | --- |
| 2026-09-10 | Механизм — декорации `afterContentClassName` + CSS `::after`, не DOM-оверлей | Прецедент ghost-текста в репо; Monaco сам позиционирует при скролле/враппинге/правках, минус хрупкость оверлея |
| 2026-09-10 | Содержимое этапа 1 — произвольный текст от 1С, без вывода типов в редакторе | Универсальный контракт «позиция → текст»; слой вывода типов подключается следующим этапом |
| 2026-09-10 | Переключатель — `setOption('showInlayHints')`, дефолт `false` | Одна точка входа, единый механизм опций; не меняет поведение по умолчанию |
| 2026-09-10 | Кликабельность через существующий `onMouseDown` + событие `EVENT_ON_INLAY_HINT_CLICK` | По образцу `diff-navi`/`add-review`; псевдоэлемент сам таргетом не бывает, класс несёт span декорации |
| 2026-09-10 | Цвет темы через статические селекторы `.vs`/`.vs-dark`, без JS-перекраски в `setTheme` | Проще и надёжнее генерации цвета на лету; декорации рендерятся внутри контейнера редактора |
| 2026-09-10 | Состав хинтов не пересчитывается при правках текста; якорь `NeverGrowsWhenTypingAtEdges` | Обновление — ответственность 1С (по `EVENT_CONTENT_CHANGED`); якорь не «расползается» при вводе в позицию хинта |
| 2026-09-10 | Набор хинтов хранится в контроллере вкладки, без `TAB_STATE_KEYS` | Декорации живут на модели вкладки и переживают переключения; глобальное состояние не нужно |
| 2026-09-10 | `getState().hintsCount` — нормализованные хинты (структурно валидные), `renderedCount` — отрисованные | Позиции вне модели известны только при отрисовке (модель может меняться); семантика зафиксирована тестом |
| 2026-09-10 | Поле `event_params`: произвольное значение прокидывается в событие клика; отсутствует/`null` → хинт не кликабельный (`pointer-events: none`, без класса `bsl-inlay-hint-clickable`) | Запрос мейнтейнера: клик имеет смысл только когда 1С ожидает параметры; служебные поля события остаются |
| 2026-09-10 | Стили хинта: без курсива, слегка серый фон (`rgba(128,128,128,0.12/0.22)`), `padding: 0 3px`, `border-radius: 2px`, без `opacity` | Запрос мейнтейнера; «вторичность» обеспечивает фон |
| 2026-09-10 | Опция `showInlayHints` убрана: видимость определяется только наличием хинтов (`setInlayHints`/`clearInlayHints`) | Запрос мейнтейнера; опция дублировала управление видимостью и создавала ловушку «вернул true, но ничего не рисуется» при вызове без включенной опции |
