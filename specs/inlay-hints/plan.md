# inlay-hints: план реализации и решения

Транзиентный спутник [`spec.md`](spec.md). Живёт до закрытия задачи; после merge либо удаляется,
либо уезжает в `specs/done/inlay-hints/plan.md` как архив развития.

Порт реализации с `webpack_0_20`@0db4b93 (декорации + CSS `::after`) на штатный API Monaco 0.55.1.

## 1. План реализации

### Этап 1. Провайдер и контроллер `src/inlay_hints.js`

- Шаги: `parseInlayHints` — без изменений против 0.20 (JSON-строка/массив, нормализация,
  `{ error }` без выбросов; CSS-экранирование не нужно). Хранилище `Map<модель, набор>` +
  один провайдер с `onDidChangeInlayHints` (самописный мини-IEvent: штатный `Emitter` не входит
  в публичный API); `createInlayHintsController(codeEditor)` — `setHints`/`clear`/`dispose`/
  `getState`, клик-обработчики.
- Gate: контроллер вручную проверяется в консоли DevTools на `npm run debug`.

### Этап 2. Интеграция `src/editor.js`

- Шаги: регистрация провайдера рядом с `registerInlineCompletionsProvider` (селектор `'*'`);
  контроллер в `initEditorEventListenersAndProperies`; `window.setInlayHints` /
  `window.clearInlayHints` (после `triggerInlineSuggestions`); dispose контроллера в
  `disposeEditorInstance`; опция `inlayHints: { maximumLength: 0 }` в `createEditorInstance`.
- Gate: мост живой — функции на `window`, события доходят до `events_queue`.

### Этап 3. Документация

- Шаги: `docs/inlay_hints.md` (порт с 0.20, контракт не менялся); README — две строки в таблицу
  функций.
- Gate: доки в тон существующих.

### Этап 4. Тесты и гейты

- Шаги: `describe` в `src/test.js`: установка/очистка, `getText` без текста хинтов, клик
  (обычный) с `event_params` и без, невалидный вход, позиции вне модели, JSON-строка, вкладки.
  Рендер асинхронный (дебаунс `InlayHintsController` ~25 мс) — везде `waitFor`; DOM-утверждения
  по спанам injected text (`[class^="dyn-rule-"]` в `.view-lines`, текст с неразрывными
  пробелами).
- Gate: `npm run test`, `build:test` + `test:mocha`, `escheck`, `build`, `test:headless`; мост
  на `window` проверен после сборки.

## 2. Риски и снижение

- Рисование асинхронное (дебаунс контроллера Monaco) — тесты поллерят DOM через `waitFor`,
  синхронных утверждений о рендере нет.
- `e.target.detail.injectedText` и `attachedData.item.hint` — внутренняя структура рендера
  0.55.1: чтение с защитными проверками на каждом уровне, опознание своего хинта по маркеру
  `__bslConsoleInlayHint` на объекте InlayHint. Fallback при изменении структуры — хинт
  не опознается, обычный клик не сработает (Ctrl+клик через command продолжит работать);
  покрывается тестами.
- Два провайдера-источника события (обычный клик + command при клике с модификатором):
  дубль исключён — обычный путь гасится при зажатом Ctrl/Alt/Cmd.
- Вкладки: редакторы не диспозятся при переключении (скрываются DOM), модели живут —
  хранилище по модели переживает переключения; очистка в `disposeEditorInstance`.
- Штатная обрезка длины хинтов строки (43) и паддинг — обрезка снята опцией
  `maximumLength: 0`, паддинг оставлен (фон со скруглением, вид VS Code).

## 3. Открытые вопросы

- Требуется ручная проверка в поле 1С (8.3.24 и 8.3.27+) — за мейнтейнером.
- Следующий этап (автотипы у присваиваний через слой `specs/type-inference`) — отдельная спека.

## 4. Решения

| Дата | Решение | Причина |
| --- | --- | --- |
| 2026-09-10 | Механизм — `registerInlayHintsProvider` + штатный `InlayHintsController`, не декорации `::after` | В 0.55 есть нативный API: рендер, темы, скролл/враппинг/правки и клик-жесты — силами Monaco |
| 2026-09-10 | Набор хранится в `Map<модель, набор>`, провайдер зарегистрирован на `'*'` | Вкладка = редактор + модель; язык значения не имеет, у моделей без набора провайдер возвращает пусто |
| 2026-09-10 | Якорь хинта — невидимая декорация модели (`NeverGrowsWhenTypingAtEdges`), позиция для провайдера читается через `getDecorationRange` | `InlayHintsController` перезапрашивает провайдера после правок; без якоря хинты «прыгали» бы на исходные позиции. Декорация на модели, а не редакторе — переживает переключение вкладок (редакторы скрываются, не диспозятся) |
| 2026-09-10 | Обновление рендера — через `onDidChangeInlayHints` (самописный мини-IEvent) | Штатный триггер перезапроса контроллера Monaco; `Emitter` не экспортирован публично |
| 2026-09-10 | Кликабельность: обычный клик — свой `onMouseDown`/`onMouseUp` (mousedown+mouseup на одном хинте, без модификаторов); клик с модификатором — штатный `command` label part + глобальный `monaco.editor.addCommand` | Паритет UX с 0.20 (обычный клик); command даёт нативное подчёркивание при наведении и Ctrl/Cmd-клик без собственного кода жестов; дубль события исключён гашением обычного пути при модификаторе |
| 2026-09-10 | Состав хинтов не пересчитывается при правках текста; якорь `NeverGrowsWhenTypingAtEdges` | Обновление — ответственность 1С (по `EVENT_CONTENT_CHANGED`); якорь не «расползается» при вводе в позицию хинта. Унаследовано из решений 0.20 |
| 2026-09-10 | `maximumLength: 0` в опциях редактора | Штатная обрезка 43 символа на строку — регресс против 0.20 (там обрезки не было) |
| 2026-09-10 | `paddingLeft/paddingRight: true` у хинтов | Фон со скруглением как у инлей-хинтов VS Code — визуальный паритет с фоном 0.20-реализации |
| 2026-09-10 | `getState().hintsCount` — нормализованные хинты (структурно валидные, включая позиции вне модели) | Семантика зафиксирована тестом в 0.20; `renderedCount`/`cssText` ушли — рендер асинхронный и внутренний |
| 2026-09-10 | Свои CSS-стили не добавляются | Цвета/фон/скругление — штатные цвета инлей-хинтов тем (наследуются базовыми `vs`/`vs-dark`) |
| 2026-09-10 | Поле `event_params`: произвольное значение прокидывается в событие клика; отсутствует/`null` → хинт не кликабельный | Унаследовано из решений 0.20 (запрос мейнтейнера): клик имеет смысл только когда 1С ожидает параметры |
| 2026-09-10 | В событии клика `line`/`column` — исходные позиция из набора, не текущая позиция якоря | Паритет с 0.20; 1С адресует ответ теми же координатами, что посылал |
