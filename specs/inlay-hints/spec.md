# inlay-hints: текстовые подсказки в строках кода (Monaco 0.20)

Стабильный контракт: что должно быть реализовано и как вызывающий код/пользователь это видит.
Переживает merge, уезжает в `specs/done/inlay-hints/spec.md`. Транзиентное (этапы, вопросы,
решения) — в [plan.md](plan.md).

## 1. Контекст и проблема

В Monaco Editor 0.20 нет API инлей-хинтов (`InlayHintsProvider` появился в Monaco ~0.25). При этом
консоли на ветке `webpack` (Monaco 0.55) планируют использовать инлей-хинты, и треку 0.20 нужен
совместимый по смыслу механизм: короткие текстовые подсказки (типы переменных, результаты вывода,
диагностика), отображаемые прямо в строках кода, без изменения текста модели.

Содержимое хинтов на этом этапе **передаёт 1С** — редактор не вычисляет текст сам. Это делает
механизм универсальным: типы переменных (сло вывода типов `specs/type-inference`), счётчики,
произвольная диагностика — всё сводится к списку «позиция → текст».

Механизм отрисовки — декорации `afterContentClassName` + CSS `::after` (прецедент в репозитории:
ghost-текст inline-подсказок, `createInlineGhosttextRenderer` в `src/editor.js`). Декорации
позиционируются самим Monaco при скролле, враппинге и правках текста — отдельный DOM-оверлей
с пересчётом координат не нужен.

## 3. Поведение

### 3.1. Основной сценарий

1. 1С вызывает `setInlayHints(hints)` с массивом (или JSON-строкой) хинтов.
2. Редактор рисует текст каждого хинта **после** указанной колонки указанной строки: текст
   в цвете темы на слегка сером фоне, визуально «приклеен» к строке, прокручивается и сворачивается
   вместе с кодом. Хинт не является текстом модели: `getText()` его не возвращает, поиск/замена,
   форматирование и подсветка синтаксиса его не затрагивают, ввод с клавиатуры невозможно
   «попасть» в хинт — якорь хинта следует за правками текста.
3. Клик по кликабельному хинту генерирует событие `EVENT_ON_INLAY_HINT_CLICK` с параметрами
   хинта и прокинутым значением `event_params`. Кликабельный — только хинт с заданным
   `event_params` (отсутствует или `null`): у остальных клики проходят сквозь в редактор.
4. Повторный вызов `setInlayHints` полностью заменяет предыдущий набор. `clearInlayHints()` убирает все.
5. Набор хинтов хранится на вкладке: переключение вкладок и возврат сохраняет отрисовку каждой вкладки.

### 3.2. Граничные случаи

- Позиция вне модели (строка/колонка за пределами текста) — хинт пропускается, остальные рисуются.
- Элемент без обязательных полей `line`/`column`/`text` — пропускается, остальные рисуются.
- Пустой массив — эквивалентен `clearInlayHints()`, возвращает `true`.
- Текст с двойными кавычками и обратными слэшами корректно экранируется в CSS `content`.
- Управляющие символы (переводы строк, табуляция) в тексте заменяются пробелами — хинт однострочный.
- Несколько хинтов в одной строке — рисуются все, в порядке следования колонок.
- Два хинта на одной и той же позиции (строка + колонка) визуально совмещаются в один
  (особенность рендера `afterContentClassName` в Monaco 0.20); различные позиции нужны
  для раздельного отображения.
- Хинт без `event_params` (отсутствует или `null`) — не кликабельный: без класса
  `bsl-inlay-hint-clickable`, `pointer-events: none`, клики проходят сквозь в редактор как обычно.
- Режим «только чтение» — хинты рисуются, клики работают.
- Режим сравнения (`compare`) — хинты не рисуются, `setInlayHints` возвращает `false`.
- Правки текста не пересчитывают состав хинтов автоматически: якоря следуют за текстом
  (обновление набора — повторный вызов `setInlayHints` со стороны 1С, например по
  `EVENT_CONTENT_CHANGED`).
- Переключение темы — цвет подстраивается автоматически (селекторы `.vs` / `.vs-dark`).
- Язык вкладки (BSL, язык запросов, DCS) не влияет: позиции адресуют модель как есть.

### 3.3. Ошибки

- Невалидный JSON или не-массив — возвращается `{ errorDescription }`, предыдущий набор не меняется.
- Вызов до инициализации редактора или в режиме сравнения — возвращается `false`.

## 4. Контракты

### 4.1. Экспортные функции моста (`window` / `defaultView`)

```js
/**
 * Показывает инлей-хинты — короткие текстовые подсказки в строках кода.
 * Полностью заменяет предыдущий набор.
 * @param {string|Array<{line: number, column: number, text: string, id?: string|number, event_params?: *}>} hints
 *   массив хинтов или JSON-строка с ним. line — строка (1-based), column — колонка (1-based),
 *   после которой выводится текст (для конца строки — длина строки + 1);
 *   text — однострочный текст подсказки; id — необязательный идентификатор для события клика;
 *   event_params — произвольное значение, прокидываемое в событие клика без изменений
 *   (хинт с незаданным event_params — отсутствует или null — не кликабельный).
 * @returns {boolean|{errorDescription: string}} true — набор принят; false — редактор
 *   недоступен или режим сравнения; {errorDescription} — ошибка разбора.
 */
function setInlayHints(hints) { ... }

/**
 * Убирает все инлей-хинты текущей вкладки.
 * @returns {boolean} true
 */
function clearInlayHints() { ... }
```

### 4.2. События (`EVENT_*`) / формат обмена с 1С

| Событие / поле | Направление | Payload | Описание |
| --- | --- | --- | --- |
| `EVENT_ON_INLAY_HINT_CLICK` | JS → 1С | `{ id, line, column, text, event_params }` | Клик по кликабельному инлей-хинту: поля хинта (`id` — `null`, если не задан) и значение `event_params` без изменений |

### 4.3. Контракт сборки / доставки

- Используется только API Monaco 0.20.0 (`deltaDecorations`, `afterContentClassName`,
  `TrackedRangeStickiness`), без API более новых версий.
- Итоговый JavaScript — ES2015 (проверка `npm run escheck`), без новых внешних ассетов —
  single-file-сборка (`build:single`, `build:pack`) не меняется.
- Новых воркеров и чанков не появляется.

## 5. Критерии приёмки

- [ ] `setInlayHints([...])` рисует хинты в редакторе (`npm run debug`, обе темы — светлой и тёмной).
- [ ] Хинты прокручиваются вместе с кодом, переживают правки соседнего текста, исчезают при
      `clearInlayHints()`.
- [ ] `getText()` не содержит текста хинтов.
- [ ] Клик по кликабельному хинту (с `event_params`) кладёт `EVENT_ON_INLAY_HINT_CLICK`
      с параметрами хинта и `event_params` в `eventData1C`; клик по некликабельному проходит
      сквозь в редактор.
- [ ] Вкладки: набор каждой вкладки не зависит от соседних.
- [ ] Гейты: `npm run test` , `build:test` + `test:mocha`, `escheck`, `build`, `test:headless`.

## 6. Вне области

- Автоматическое вычисление текста хинтов в редакторе (типы переменных через `getInferredContext`
  и т.п.) — возможный следующий этап; контракт `setInlayHints` проектируется переиспользуемым.
- Имена параметров у вызовов методов.
- Тултипы при наведении на хинт, контекстное меню хинта.
- Блокировка перемещения курсора при клике по хинту (клик также ставит курсор в строку —
  как у существующих кликабельных декораций `diff-navi`).
- Горячие клавиши, модификация сборки/патчей Monaco.
