# query-params-tooltips: тултипы параметров запроса поверх inlay-hints

Стабильный контракт: что должно быть реализовано и как вызывающий код/пользователь это видит.
Переживает merge, уезжает в `specs/done/query-params-tooltips/spec.md`. Транзиентное (этапы, вопросы,
решения) — в [plan.md](plan.md).

## 1. Контекст и проблема

Консоли запросов показывают текст запроса, в котором параметры выглядят как `&Параметр` без всякого
представления об их фактических значениях. 1С знает значения (ссылка, дата, представление), редактор —
нет. Нужна функция, по которой 1С передаёт список «параметр → представление (→ значение)», а редактор
сам находит вхождения параметров в тексте запроса и рисует рядом с ними инлей-хинты
(механизм [specs/inlay-hints](../inlay-hints/spec.md)).

Отличие от `setInlayHints`: позиции не передаются — редактор вычисляет их сам по тексту модели и
**пересчитывает при каждом изменении текста** (переименование/удаление параметра, вставка строк выше,
новые вхождения).

## 3. Поведение

### 3.1. Основной сценарий

1. Режим редактора — `bsl_query` или `dcs_query`. 1С вызывает
   `setQueryParamsTooltips(params)` с массивом (или JSON-строкой) элементов
   `{ param, label, value?, tooltip? }`.
2. Редактор ищет в тексте модели все вхождения `&<param>` (по одному regex на весь набор,
   с границей имени: `&Парам` не матчится внутри `&Параметр`) и рисует инлей-хинт сразу после
   каждого вхождения: `text = label`, `id = param`, `event_params = value`, `tooltip = tooltip`.
3. Хинт с заданным `value` — кликабельный: **обычный** клик (без модификатора) генерирует
   `EVENT_ON_INLAY_HINT_CLICK` со всеми полями хинта (`id` — имя параметра) и
   `event_params = value` без изменений; курсор над таким хинтом — pointer (как у прочих
   кликабельных инлей-хинтов на Monaco 0.20). Хинт без `value` (отсутствует или `null`) —
   некликабельный, клики проходят сквозь, курсор не меняется.
4. Заданный `tooltip` (markdown-строка) — всплывающая подсказка при наведении на хинт: штатный
   markdown-рендерер Monaco с очисткой HTML (выделение, код, списки, таблицы; `http/https`-
   ссылки кликабельны, `command:`-ссылки заблокированы). Показывается у каждого вхождения
   параметра. Над хинтом — **только** она: hover-провайдеры языка запроса на позиции якоря
   подавлены (иначе слово параметра — например, совпавшее со ссылкой-параметром в SELECT,
   `getQueryModelSelectItemByWord` — добавляет вторую строку в hover-виджет). `tooltip` не
   задан — наша подсказка не появляется, подавления нет: штатный hover слова запроса у
   позиции параметра показывается как обычно (существующее поведение, не связано с фичей).
5. При каждом изменении текста модели состав и позиции пересчитываются автоматически: якорь
   следует за текстом, тултип исчезает у переименованного/удалённого параметра, появляется у
   нового вхождения, дублируется при повторном вхождении (например, в частях UNION).
6. Один параметр, встречающийся несколько раз, получает тултип у **каждого** вхождения.

### 3.2. Граничные случаи

- Один общий набор с `setInlayHints`: тултипы параметров занимают набор инлей-хинтов целиком.
  Повторный `setInlayHints` стирает их и отменяет автопересчёт до нового вызова
  `setQueryParamsTooltips`; `clearInlayHints` убирает всё и также отменяет автопересчёт.
- Вызов вне режимов `bsl_query`/`dcs_query` — возвращает `false`, набор не запоминается.
- `setLanguageMode` в режим, отличный от режимов запроса, — набор параметров забывается,
  инлей-хинты очищаются (в т.ч. ручные — набор общий; переустановить их повторным вызовом).
- Пустой массив — эквивалентен `clearInlayHints()`, возвращает `true`.
- Элемент без обязательных полей `param` (непустая строка) или `label` (непустая строка) —
  пропускается; `value` — произвольное значение, необязательное; `tooltip` — строка (markdown)
  или null, необязательное.
- Параметры, не найденные в тексте, молча игнорируются (без ошибок).
- Вхождение внутри строкового литерала или комментария не отличают от прочих — поиск по всему
  тексту модели (упрощение первого этапа).
- Режим сравнения (`compare`) и вкладки: как у `setInlayHints` — в compare `false`; набор хранится
  на редакторе вкладки, изоляция вкладок автоматическая.
- Переключение темы — как у прочих инлей-хинтов.

### 3.3. Ошибки

- Невалидная JSON-строка или не-массив — `{ errorDescription }`, предыдущий набор не меняется.
- Вызов до инициализации редактора, в режиме сравнения или вне режимов запроса — `false`.

## 4. Контракты

### 4.1. Экспортные функции моста (`window` / `defaultView`)

```js
/**
 * Показывает тултипы значений параметров запроса (&Параметр) как инлей-хинты.
 * Работает только в режимах bsl_query / dcs_query. Позиции вычисляются по тексту модели
 * и пересчитываются при каждом его изменении. Занимает набор инлей-хинтов целиком
 * (см. setInlayHints). Опциональное поле tooltip (markdown-строка) — всплывающая
 * подсказка хинта при наведении (http/https-ссылки кликабельны, command: — заблокированы).
 * @param {string|Array<{param: string, label: string, value?: *, tooltip?: string}>} params
 *   массив (или JSON-строка) описаний: param — имя параметра без &; label — текст тултипа;
 *   value — произвольное значение, прокидываемое в событие клика как event_params
 *   (хинт с незаданным value не кликабельный); tooltip — markdown-строка всплывающей
 *   подсказки при наведении (отсутствует/null — подсказки нет).
 * @returns {boolean|{errorDescription: string}} true — набор принят; false — редактор
 *   недоступен, режим сравнения или не режим запроса; {errorDescription} — ошибка разбора.
 */
function setQueryParamsTooltips(params) { ... }
```

### 4.2. События (`EVENT_*`) / формат обмена с 1С

Переиспользуется событие `EVENT_ON_INLAY_HINT_CLICK` (см. [specs/inlay-hints](../inlay-hints/spec.md)):
`{ id: <имя параметра>, line, column, text: <label>, event_params: <value> }`.

### 4.3. Контракт сборки / доставки

- Используется только API Monaco 0.20.0 (`model.findMatches`, `deltaDecorations`,
  `afterContentClassName`, `registerHoverProvider`), без API более новых версий.
- Итоговый JavaScript — ES2015 (проверка `npm run escheck`), без новых внешних ассетов —
  single-file-сборка (`build:single`, `build:pack`) не меняется. Новых воркеров и чанков нет.

## 5. Критерии приёмки

- [ ] `setQueryParamsTooltips([...])` в `bsl_query`/`dcs_query` рисует тултип после каждого
      вхождения `&Параметр` (`npm run debug`, обе темы).
- [ ] Вставка строки выше вхождения смещает тултип вместе с параметром; переименование параметра
      убирает тултип, новое вхождение — добавляет, без повторного вызова из 1С.
- [ ] Клик по тултипу с `value` кладёт `EVENT_ON_INLAY_HINT_CLICK` c `text = label`,
      `event_params = value`, `id = <имя параметра>`; без `value` — клики сквозь.
- [ ] Наведение на тултип с `tooltip` показывает markdown-подсказку (`npm run debug`, обе
      темы): выделение, код, списки; `http/https`-ссылки кликабельны, `command:` — нет;
      над тултипом с `value` курсор pointer.
- [ ] Классический `setInlayHints` не изменился: поле `tooltip` у его хинтов семантики
      не меняет, markdown-подсказка не включается.
- [ ] Вызов в режиме `bsl` возвращает `false`; `setLanguageMode('bsl')` очищает тултипы.
- [ ] `setInlayHints` после `setQueryParamsTooltips` заменяет набор и отключает автопересчёт;
      `clearInlayHints` убирает всё.
- [ ] `&Парам` не совпадает с `&Параметр`.
- [ ] Гейты: `npm run test`, `build:test` + `test:mocha`, `escheck`, `build`, `test:headless`.

## 6. Вне области

- Подсветка/навигация по параметрам, различение вхождений в строках и комментариях.
- Отдельная функция `clearQueryParamsTooltips` — очистка через `clearInlayHints()` или
  `setQueryParamsTooltips([])`.
- Слияние двух слоёв хинтов (ручного и параметрического) в один экран — набор общий.
- Автозаполнение списка параметров из текста запроса (1С передаёт список целиком).
