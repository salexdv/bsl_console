# query-params-tooltips: план реализации и решения

Транзиентный спутник [`spec.md`](spec.md). Живёт до закрытия задачи; после merge либо удаляется, либо
уезжает в `specs/done/query-params-tooltips/plan.md` как архив развития. Сюда — то, что мешает читать
стабильный контракт: этапы работ, открытые вопросы, история решений.

## 1. План реализации

### Этап 1. Модуль и интеграция

- Шаги: `src/query_params_hints.js` (парсинг входа + контроллер, делегирующий отрисовку в
  `inlayHintsController`); хук контроллера в `initEditorEventListenersAndProperies`;
  `window.setQueryParamsTooltips`; пересчёт в `onDidChangeModelContent`; сброс набора в
  `setLanguageMode` / `setInlayHints` / `clearInlayHints`.
- Gate: ручная проверка в `npm run debug` (режим `bsl_query`, правки текста, клики).

### Этап 2. Тесты и доки

- Шаги: кейсы в `src/test.js` (страница `/test` — единственная, покрываемая гейтом `test:mocha`;
  `test_query.html` гейтом не прогоняется) — отрисовка, смещение при правках, клики, гейты режимов,
  сосуществование с `setInlayHints`; `docs/query_params_tooltips.md`, строка в `README.md`,
  заметка в `docs/inlay_hints.md`.
- Gate: `npm run test`, `build:test` + `test:mocha`, `escheck`, `build`, `test:headless`.

### Этап 3. Markdown-tooltip при наведении (2026-09-16, порт af26823 с ветки webpack/Monaco 0.55)

- Контракт расширен полем `tooltip` (markdown-строка): наведение на тултип параметра показывает
  markdown-подсказку штатным hover-виджетом Monaco (рендер, sanitize, кликабельность ссылок —
  как у нативного hover).
- Реализация на 0.20 отличается от 0.55 (там — штатное поле `InlayHint.tooltip` у injected text):
  ленивый hover-провайдер (`registerHoverProvider` для `bsl_query`/`dcs_query`) с двойным гейтом —
  «мышь сейчас над этим хинтом» (DOM-детект в `handleMouseMove` по классам декорации, тем же
  механизмом, что клики) и «позиция запроса = якорь хинта».
- Маркер `bsl-inlay-hint-with-tooltip` включает `pointer-events: auto` у `::after` хинта с
  tooltip в QP-наборе: без него некликабельный хинт (`pointer-events: none`) не детектится
  мышью. Курсор не меняется — pointer у кликабельных уже есть (см. решения).
- Gate: `build:test` + `test:mocha`, `escheck`, `build`; ручная проверка hover в `npm run debug`
  (обе темы, ссылки в markdown).

### Риски и снижение

- Офф-бай-один позиции хинта (семантика `afterContentClassName` в Monaco 0.20): колонка хинта —
  `range.endColumn` вхождения, что согласовано с докой `setInlayHints` («для конца строки —
  длина строки + 1»); дополнительно проверено визуально и тестом позиции.
- Декорации и так следуют за текстом; пересчёт нужен именно для состава (переименование/удаление/
  новые вхождения) — пересчёт делегирует в `setHints`, полный ре-рендер набора.

## 3. Решения

| Дата | Решение | Причина |
| --- | --- | --- |
| 2026-09-10 | Один общий набор с `setInlayHints`, без слоя слияния | Проще и предсказуемее; контракт `setInlayHints` («полностью заменяет») не меняется |
| 2026-09-10 | Вне режимов запроса — `false`, набор не хранится; смена режима из запроса очищает хинты | `&Параметр` вне языка запросов бессмыслен; строгий гейт как у compare-режима |
| 2026-09-10 | Тултип на каждом вхождении параметра | Повторные вхождения типичны (UNION, повторные секции) |
| 2026-09-10 | Очистка через `clearInlayHints` / `setQueryParamsTooltips([])`, без отдельной clear-функции | Единая точка очистки; набор общий |
| 2026-09-10 | Поиск по всему тексту, без исключения строк/комментариев | Упрощение первого этапа; отмечено вне области спеки |
| 2026-09-10 | Интеграционные тесты — в `src/test.js`, а не `src/test_query.js` | `test:mocha` прогоняет только страницу `/test`; прецедент — тесты inlay-hints живут в `src/test.js`, режим запроса включается в `beforeEach` |
| 2026-09-16 | Markdown-tooltip — через hover-провайдер `registerHoverProvider` (`bsl_query`/`dcs_query`), а не своё popup-окно | На Monaco 0.20 нет `InlayHint.tooltip`/injected text; провайдер даёт штатный markdown-рендерер Monaco с `sanitize:true` и блокировкой `command:`-ссылок без `isTrusted` (http/https кликабельны) — паритет семантики 0.55 без патчей Monaco и собственного санитайзера |
| 2026-09-16 | Двойной гейт провайдера: DOM-детект хинта под мышью (`handleMouseMove`/`handleMouseLeave`, классы декорации) + совпадение позиции запроса с якорем | Позиция мыши над `::after`-псевдоэлементом разрешается Monaco в якорь хинта (mouseTarget.js, `caretRangeFromPoint` в граничную колонку пустого span декорации), но позиция соседнего символа тоже равна якорю — без DOM-гейта подсказка мигала бы на соседнем символе |
| 2026-09-16 | Маркер `bsl-inlay-hint-with-tooltip` + `pointer-events: auto` у `::after` (decorations.css), только для QP-наборов | У некликабельного хинта `::after` по умолчанию `pointer-events: none` — событие мыши проваливается мимо span декорации, DOM-детект (и hover-подсказка у тултипа без `value`) не срабатывает; классические наборы не затронуты |
| 2026-09-16 | pointer-курсор над кликабельными хинтами НЕ ограничивается QP-наборами (расхождение с тестом af26823 на 0.55) | На 0.20 pointer у кликабельных хинтов существовал до этого этапа (decorations.css, `::after`-курсор) и был единственным аффордансом кликабельности — у хинтов 0.20 нет command-ссылки с подчёркиванием, как на 0.55. Убирать его у классических `setInlayHints` — изменение существующего поведения вне области порта |
| 2026-09-16 | Разделение режимов наборов — флагом `queryParams` в `setHints(value, options)` (паритет с 0.55-реализацией af26823), поле `tooltip` проносится общим парсером, но у классических наборов игнорируется | `window.setInlayHints` зовёт без опций → поведение прежнее; поле входа `tooltip` у классического набора семантики не меняет (документировано только для QP) |
| 2026-09-16 | Приняты нативные артефакты hover 0.20: (а) у позиции якоря показывается штатный hover слова запроса (`&БезНДС`) — существующее поведение, наша подсказка аддитивна; (б) переход мыши с текста параметра на хинт может не сменить содержимое (фильтр сообщений `startShowingAt` по диапазону слова); (в) смена набора при неподвижной мыши над хинтом оставляет старый hover до движения (same-range оптимизация) | Паритет с нативным поведением word-hover 0.20; обход требует патчей внутренних классов Monaco. Сквозная проверка реальными событиями мыши (headless Chrome, /test после mocha) подтвердила все основные сценарии: markdown/ссылки/pointer/скрытие/некликабельный хинт |
| 2026-09-16 | Над хинтом с tooltip hover-провайдеры языка запроса (`bsl_language.js`, bsl_query/dcs_query) подавлены на позиции якоря — guard `queryParamsTooltipHover` из `inlay_hints.js` (то же условие, что у провайдера markdown-подсказки) | Позиция якоря — та же, где срабатывает штатный hover слова параметра: совпадение со ссылкой-параметром в SELECT (`getQueryModelSelectItemByWord`) добавляло вторую строку в hover-виджет рядом с tooltip. Вне хинта (наведение на текст параметра) hover слова работает как прежде; без tooltip подавления нет |
| 2026-09-16 | Гейт позиции запроса ослаблен: валидны якорь и якорь−1 (строка — строго), а не только якорь | Воспроизведено headless-экспериментом на реальном Monaco 0.20 (CDP mouse events): у хинта в **середине** строки `::after`-чип занимает место между якорем C и колонкой C−1, hit-test (mouseTarget.js) брекетует якорь соседними колонками → CONTENT_TEXT с диапазоном (C−1, C), и hover-виджет (modesContentHover.js) запрашивает провайдеров на `range.startColumn` = C−1. Строгий гейт «колонка == якорь» отбрасывал запрос — тултип не показывался у параметров не в конце строки (например, `МЕЖДУ &НачалоГода И &КонецМесяца`). У хинтов в конце строки диапазон коллапсирован на якоре — работали и раньше. Ложные срабатывания отсекает DOM-гейт (мышь над самим хинтом) |
