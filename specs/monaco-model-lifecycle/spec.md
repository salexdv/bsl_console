# monaco-model-lifecycle: владение и освобождение Monaco-моделей

## 1. Контекст и проблема

Monaco не освобождает модели, переданные редактору извне через `setModel()`, и хранит созданные
`createModel()` экземпляры до явного `dispose()`. После исправления повторного создания original-модели
в PR #396 в проекте остаются временные модели и вспомогательные diff-редакторы без полного teardown.
Повторный вызов соответствующих сценариев увеличивает число моделей и удерживаемую память.

## 2. Область изменений

| Компонент | Тип | Характер изменений |
| --- | --- | --- |
| `src/bsl_helper.js`, `src/bsl_language.js` | src | освобождение временных моделей |
| `src/editor.js` | src | единый lifecycle вспомогательных diff-редакторов |
| браузерные тесты | тесты | контроль числа моделей и очистка test-owned моделей |

Изменения реализуются в основной ветке `webpack` и адаптируются для поддерживаемой ветки
`webpack_0_20` с учётом различий Monaco 0.55 и 0.20.

## 3. Поведение

### 3.1. Владение моделями

1. Код, вызвавший `monaco.editor.createModel()`, владеет моделью до явной передачи владельцу.
2. Временная модель освобождается в `finally`, включая выход по исключению.
3. Вспомогательный diff-редактор владеет созданной original-моделью, но заимствует modified-модель
   основного редактора и не имеет права её освобождать.
4. Замена original-модели освобождает предыдущую после успешной установки новой.

### 3.2. Завершение diff-сценариев

- Закрытие встроенного diff-виджета освобождает его редактор и original-модель.
- Отключение diff-декораций, очистка исходного текста и пересоздание основного редактора освобождают
  скрытый diff-редактор и его original-модель.
- Отложенный callback не создаёт редактор или модель после закрытия виджета либо смены основного редактора.

### 3.3. Ошибки

- Если передача новой модели в diff-редактор завершается ошибкой, новая модель освобождается вызывающим
  кодом, а существующая рабочая пара моделей не уничтожается.
- Повторный teardown безопасен и пропускает уже освобождённые модели.

## 4. Контракты

Публичные функции моста `window`, события `EVENT_*`, формат данных и сборки не меняются. Добавляются
только внутренние функции управления ресурсами.

## 5. Критерии приёмки

- [x] Повторные вызовы временного анализа не увеличивают `monaco.editor.getModels().length`.
- [x] Повторное открытие и закрытие встроенного diff не увеличивает число моделей и diff-редакторов.
- [x] Очистка original-текста и отключение diff-декораций возвращают число моделей к исходному уровню.
- [x] Быстрое закрытие виджета до срабатывания таймера не оставляет редакторов и моделей.
- [x] Браузерные тесты освобождают модели, созданные тестовыми helper-функциями.
- [x] Полный набор тестов, production-сборка и ES-floor проходят в обеих поддерживаемых ветках.

## 6. Вне области

- Внутренний lifecycle Monaco и содержимое `node_modules`.
- Однократно создаваемые модели демонстрационных страниц, живущие до закрытия самой страницы.
- Автоматическое сравнение точного размера heap: проверяется отсутствие остающихся моделей и редакторов.
