## Как читать оценки

**Сложность** (грубая, «инженеро-дни» без учёта согласований и полевых прогонов в 1С):

| | Значение |
| --- | --- |
| **S** | часы; локальная правка/данные, малый риск |
| **M** | день–два; один-два модуля, нужна проверка в поле 1С |
| **L** | неделя+; новая подсистема или изменение модели данных/контракта |
| **XL** | крупный проект или **блокировано платформой** (WebKit/версия Monaco) |

**Метки:** 🟢 быстрый выигрыш · 📦 в основном данные (низкий риск) · 🔒 упирается в движок
поля 1С (старый WebKit) или в версию Monaco · 🌐 paste1c.ru (вне кода редактора) · ✅ уже сделано.

Ключевой контекст, который «красит» половину бэклога: **много перф-/фичевых задач блокированы
старым WebKit в «Поле HTML документа»**. WebKit2 для Windows перенесён 1С на 8.5.4 (см. #185).
Всё, что требует Monaco ≥ 0.34 (InlineCompletions, часть тем diff), не поедет, пока платформа не
обновит движок либо пока не будет доведён спайк 0.55 ([`specs/monaco-0.55/`](../monaco-0.55/spec.md)).

### 🟢 #325 — сборка webpack на Node 18+ (openssl)

**Причина.** webpack 4 использует алгоритмы, которые OpenSSL 3 (Node 17+) считает legacy →
`ERR_OSSL_EVP_UNSUPPORTED`. Обход уже отработан: под сборку берём **Node 16** (nvm-windows).

**Оценка:** S (правка скриптов + строка в доке).

**Набросок.** Два варианта, можно оба:

1. Зафиксировать Node в репозитории — `.nvmrc`:
   ```
   16
   ```
   и `engines` в `package.json`:
   ```json
   "engines": { "node": ">=14 <17" }
   ```
2. Сделать скрипты самодостаточными на новых Node через `cross-env`:
   ```json
   "scripts": {
     "build": "cross-env NODE_OPTIONS=--openssl-legacy-provider webpack --config webpack.config.js --mode production",
     "debug": "cross-env NODE_OPTIONS=--openssl-legacy-provider webpack serve --mode development"
   }
   ```
   (`cross-env` — чтобы работало и в cmd/PowerShell, и в bash; `set NODE_OPTIONS=... &&` из комментария
   к issue ломается в не-Windows.)

Плюс строка в README-раздел сборки: «Node 16 рекомендуется; на Node 17+ — флаг `--openssl-legacy-provider`».

### #305 — залипание контекстной подсказки (ТаблицаЗначений/ДеревоЗначений)

**Симптом.** После
```
ТЗ = Новый ТаблицаЗначений();
ТЗ.Колонки.Добавить("Имя");
ТЗ.
```
подсказка на `ТЗ.` показывает свойства **колонки**, а не методы ТаблицаЗначений; причём эффект
«прилипает» и к другим переменным.

**Причина (три слоя).**
1. Кеш типов `window.contextData` (Map по номеру строки) создаётся один раз в
   [editor.js:49](src/editor.js#L49) и **никогда не инвалидируется** при правках модели
   (обработчик `onDidChangeModelContent` его не трогает).
2. В [bsl_helper.js:1660](src/bsl_helper.js#L1660) `getRefCompletionFromPosition` через
   `Finder.findPreviousMatch` заворачивается (wrap-around) на **другие строки** и достаёт `ref`
   свойства `Колонки` (`types.КоллекцияКолонокТаблицыЗначений`, [bslGlobals.js:9999](src/bslGlobals.js#L9999)).
3. Баг сравнения — [bsl_helper.js:1669](src/bsl_helper.js#L1669):
   ```js
   if (position.lineNumber = currentPosition.lineNumber) {   // = вместо ==
   ```
   Присваивание вместо сравнения: условие всегда истинно, `position.lineNumber` затирается, проверка
   «точка на текущей строке» не работает.

**Оценка:** M (риск средний — трогаем горячий путь автодополнения; нужен полевой прогон + тесты).

**Набросок (по возрастанию охвата, минимум = п.1+п.3).**

1. **Инвалидация кеша при правках.** В обработчике `onDidChangeModelContent` (около
   [editor.js:2162](src/editor.js#L2162)) чистить затронутые строки:
   ```js
   editor.getModel().onDidChangeModelContent(function (e) {
     if (window.contextData) {
       // грубо и безопасно: сбросить кеш типов при любой правке
       window.contextData.clear();
       // (тоньше — удалять только строки из e.changes[].range, но начать стоит с clear)
     }
     // ...существующая логика...
   });
   ```
   В тестах `contextData.clear()` уже используется — семантика ожидаемая.
2. **Починить сравнение** на [bsl_helper.js:1669](src/bsl_helper.js#L1669): `=` → `==`.
3. **Запрет чтения с чужих строк.** В `getRefCompletionFromPosition` после `findPreviousMatch`
   проверять `match.range.startLineNumber <= currentPosition.lineNumber` и что найденная точка
   относится к текущей цепочке, иначе игнорировать (не подхватывать последний в документе `.метод(`).

Пунктов 1+2 достаточно, чтобы закрыть основной сценарий тикета; 3 убирает остаточные ложные
срабатывания. Тест-кейсы: три примера из тела #305 (Вставить/Найти/Получить у `Колонки`).

### #316 — CTRL-hover в языке запросов показывает «определение» поля

**Симптом.** В режиме запроса CTRL+наведение на `ВалютыТ.Код` показывает бесполезный popup
(движок трактует `Код` как псевдоним и ищет `... КАК Код`).

**Причина.** Провайдер определения для запроса — `provideQueryDefinition`
[bsl_helper.js:8466](src/bsl_helper.js#L8466). Ветка «слева точка» уводит в
`getQueryFieldDefinition` ([bsl_helper.js:8387](src/bsl_helper.js#L8387)):
```js
if (this.wordHasCharsBefore('.'))
    location = this.getQueryFieldDefinition()   // ← случай ВалютыТ.Код
```
Готовые «кирпичики» уже есть: `wordHasCharsBefore('.')` / `wordHasCharsAfter('.')`.

**Оценка:** S–M.

**Набросок.**

- **Минимум (как просил автор issue):** для обращения к полю не показывать определение —
  ```js
  if (this.wordHasCharsBefore('.'))
      location = null;                 // поле таблицы: определение не показываем
  else if (this.wordHasCharsAfter('.'))
      location = this.getQuerySourceDefinition();
  else
      location = this.getQueryTempTableDefinition();
  ```
  Мягче — спрятать старое поведение под опцию (`window.editor.enableQueryFieldDefinition`),
  чтобы у тех, кому field-definition нужен, ничего не пропало.
- **Опциональное событие (просьба tormozit «событие перед показом определения»).** Важный нюанс:
  `window.sendEvent` ([editor.js:114](src/editor.js#L114)) — асинхронный fire-and-forget, синхронно
  «погасить» результат он не может (провайдер обязан вернуть значение сразу). Поэтому:
  - уведомительное `EVENT_BEFORE_SHOW_DEFINITION` (по образцу `generateDefinitionEvent`,
    [bsl_helper.js:8228](src/bsl_helper.js#L8228)) — можно добавить, но подавление всё равно делает
    сам guard выше;
  - для реального «подставить/погасить снаружи» — синхронный хук `window.editor.onBeforeShowDefinition(...)`,
    возвращающий `false`/свой location. Это отдельная фича сверх #316.

Рекомендация: для тикета достаточно guard'а; событие/хук — отдельным опциональным PR.

### #297 + #368 — опции моста и строка Напарника в списке

**#297. setOption(...,Ложь) не гасит EVENT_BEFORE_SHOW_SUGGEST → рекурсия.**

Проверено: в текущей базе `setOption` [editor.js:1373](src/editor.js#L1373) **уже синхронный** (прямое
присваивание `window.editor[optionName] = optionValue`; `setTimeout`/очереди нет). Значит обходной
`editor['generateBeforeShowSuggestEvent']=false` из комментария tormozit тут байт-в-байт равен
`setOption`. Асинхронной была прежняя версия (мотив #182 — отложенная перенастройка observer'ов).
Поэтому надёжнее лечить не «синхронностью опции», а самой рекурсией:

- **One-shot guard (рекомендуется).** В `showCustomSuggestions`
  ([editor.js:942](src/editor.js#L942)) перед `triggerSuggestions()`:
  ```js
  window.suppressBeforeShowSuggestEvent = true;
  ```
  В `onProvideCompletion` (чтение флага ~[bsl_helper.js:8060](src/bsl_helper.js#L8060)):
  ```js
  let fire_event = window.getOption('generateBeforeShowSuggestEvent');
  if (window.suppressBeforeShowSuggestEvent) { window.suppressBeforeShowSuggestEvent = false; fire_event = false; }
  ```
  Разрывает петлю независимо от тайминга опции; вызывающему больше не надо дёргать флаг вокруг
  `showCustomSuggestions`.
- Если синхронизировать саму опцию в upstream — отделить мгновенную запись значения от отложенной
  перенастройки observer'ов (у `generateBeforeShowSuggestEvent` ветки observer'а нет → регресса #182
  не будет).

**Оценка:** S–M.

**#368. Верхняя строка «Вызвать Напарника», активной остаётся 2-я строка.**

`preselect` в проекте нигде не используется, но Monaco его поддерживает нативно: первый элемент с
`preselect: true` становится активным. Достаточно прокинуть поле из входного JSON в CompletionItem —
`showCustomSuggestions`, литерал элемента около [editor.js:952](src/editor.js#L952):
```js
window.customSuggestions.push({
  label: value.name,
  kind: monaco.languages.CompletionItemKind[value.kind],
  insertText: value.text,
  insertTextRules: monaco.languages.CompletionItemInsertTextRule.InsertAsSnippet,
  detail: value.detail,
  documentation: value.documentation,
  filterText: value.hasOwnProperty('filter') ? value.filter : value.name,
  sortText: value.hasOwnProperty('sort') ? value.sort : value.name,
  preselect: value.preselect === true          // ← новое, opt-in
});
```
Тогда 1С формирует список: 1-я строка — «Вызвать Напарника» (без `preselect`), 2-я — лучшее слово
анализатора с `preselect: true`. Enter по умолчанию принимает слово анализатора; Напарник — видимой
верхней строкой. Полностью обратно совместимо. Оценка: **S**. (Проверить, что `preselect` бьёт
`suggest.selectionMode` — в 0.52/0.55 бьёт.)
