# 228: подсказка ключей структуры в методе `Свойство`

> Issue: [#228](https://github.com/salexdv/bsl_console/issues/228)
>
> Связанная работа: [PR #387](https://github.com/salexdv/bsl_console/pull/387) уже собирает
> ключи структур для подсказки через точку; эта спецификация переиспользует тот же набор внутри
> первого параметра `Свойство`.

## 1. Контекст и проблема

`updateMetadata` позволяет описать пользовательский объект со свойствами, а вывод типов умеет
собирать ключи локально созданной структуры. Эти имена предлагаются после точки, но обычный
completion внутри строкового литерала отключён, поэтому в `Параметры.Свойство("` подсказки нет.

## 2. Область изменений

| Компонент | Тип | Характер изменений |
| --- | --- | --- |
| `src/bsl_helper.js` | src | отдельный completion первого строкового параметра `Свойство` |
| `src/test.js` | тесты | сценарии `customObjects`, выведенных ключей и границ срабатывания |
| `docs/update_metadata.md`, `CHANGELOG.md` | доки | описание пользовательского сценария |

## 3. Поведение

### 3.1. Основной сценарий

В языке BSL для незакрытого первого строкового параметра вызова
`<Имя>.Свойство("...` или `<Имя>.Property("...` редактор предлагает известные ключи структуры.
Получатель поддерживается в форме простого имени объекта или переменной.

Источники имён:

1. `properties` одноимённого объекта из `bslMetadata.customObjects.items`;
2. ключи локальной переменной, выведенные из конструктора, типизирующего комментария и операций
   `Вставить`, `Удалить`, `Очистить` механизмом `type-inference`.

Для пользовательского объекта свойства метаданных образуют начальный набор, к которому по порядку
применяются операции кода выше курсора. Набранный префикс фильтрует список без учёта регистра;
completion заменяет только этот префикс и вставляет имя без кавычек.

### 3.2. Граничные случаи

- Подсказка доступна только для `classes.Структура` и `classes.ФиксированнаяСтруктура`.
- Дубликаты имён удаляются без учёта регистра.
- После закрытия первой строки, во втором параметре, у другого метода и в query/DCS подсказки нет.
- Цепочки получателя (`Контекст.Параметры`) и результаты выражений не разбираются.

### 3.3. Ошибки

Неизвестный или неструктурный получатель возвращает пустой результат и не прерывает остальные
ветки completion provider.

## 4. Контракты

Экспортные функции `window`, события `EVENT_*` и формат `updateMetadata` не меняются. Используется
существующий узел `customObjects.properties`; меняется только полнота подсказок редактора.

## 5. Критерии приёмки

- [x] `Параметры.Свойство("` предлагает свойства из `customObjects`.
- [x] `Property("` работает для английского имени метода.
- [x] Набранный префикс заменяется без изменения кавычек и остального вызова.
- [x] Ключи из конструктора, комментария и `Вставить` предлагаются; `Удалить` и `Очистить` снимают их.
- [x] Отрицательные сценарии не возвращают ключи структуры.
- [x] Зелёные `test:mocha`, `escheck` и `test:headless`.

## 6. Вне области

- Разбор составных выражений и цепочек в получателе.
- Вывод типа значения во втором выходном параметре `Свойство`.
- Изменение публичного контракта интеграции с 1С.
