# monaco-0.55: спайк апгрейда редактора

> Issue: нет (спайк). Референс [Pr-Mex/VAEditor](https://github.com/Pr-Mex/VAEditor) (BSD-3, Monaco 0.55.1
> в поле 1С). Детальная карта API-дрейфа и рецепт сборки — [`analysis.md`](analysis.md).
> План/риски — [`plan.md`](plan.md).

Это **спайк/PoC**, а не переписывание в прод: доказать выполнимость Monaco **0.55.1** в «Поле HTML
документа» 1С с функциональным паритетом bsl_console и снять риски. Итог спайка — работающая ветка-PoC +
отчёт с данными (минимальная поддерживаемая платформа, состояние macOS/Linux), на основании которых
принимается решение о судьбе апгрейда.

## 1. Контекст и проблема

bsl_console сидит на Monaco 0.20 (февраль 2020). Это даёт три хронические боли:

- **версия** — 35 миноров позади: нет новых API, фиксов, нового diff-редактора, inline suggestions;
- **macOS** — на 0.20 ломается клавиатура (keyCode-обработка Monaco);
- **Linux** — собственные обходы (класс `Finder` вместо `findMatches` и др.).

Компромисс: поле 1С рендерит старый WebKit (~Safari 11–13), а Monaco ≥0.31 собран esbuild'ом под
современные движки. Значит апгрейд = транспиляция + полифиллы + строковые патчи, и **потеря самых
старых платформ 1С**. VAEditor доказал, что Monaco 0.55.1 в поле 1С работает с **платформы 8.3.14
(рекомендуется 8.3.18+)** на Windows/Linux/macOS — это ожидаемая нижняя граница и для нас.

Позиция мейнтейнера (2026-07-12): переход на 0.55 он **не форсировал бы** — в редакторе «приличное
количество низкоуровневых твиков», и по опыту захода на 0.47 (экспериментальная ветка
`webpack-monaco-v0.47.0`, не доведена) их перенос «непросто, особенно под Linux». Поэтому спайк —
это прежде всего **данные для решения**: доказать выполнимость и замерить компромисс по платформам,
а оформление итога (апгрейд-билд или merge) — отдельное решение по результатам. Не смешивать со
single-file-работой ([`specs/single-file-build`](../single-file-build/spec.md)) — отдельные треки.

## 3. Поведение

### 3.1. Основной сценарий (этапы спайка с гейтами)

Спайк идёт по нарастанию; каждый гейт — условие продолжения (детали и оценки — plan.md):

1. **Каркас**: webpack5 + Monaco 0.55.1 + полифиллы + патчи + blob-воркер + NLS(ru) → «голый»
   редактор **открывается и печатает** в поле 1С на Windows. Провал гейта = стоп и разбор.
2. **Язык**: Monarch-грамматика BSL/запросов + темы + языковая конфигурация → подсветка работает.
3. **Провайдеры**: `bsl_helper` + данные на новом API → автодополнение, hover, подсказки параметров,
   определения, фолдинг, форматирование — в браузере.
4. **Обвязка/мост**: события `EVENT_*`, все экспортные функции `window`, сниппеты, diff/compare,
   контекстное меню, keybindings, статусбар/виджеты → функциональный паритет в браузере и в поле 1С.
5. **Кросс-платформа**: Windows (8.3.27+, «Защита от опасных действий» ВКЛ), Linux-контейнер,
   macOS (проверка клавиатуры — одна из целей спайка); замер минимальной работающей платформы.
6. **Итог**: отчёт с данными + решение об оформлении апгрейда; перенос single-file-таргета на новый стек.

### 3.2. Граничные случаи

- **Кириллица**: unicode highlighting 0.55 гасится опциями (иначе весь текст в «двойниках»);
  подсказки/параметры с кириллическими именами — работают (см. патч parameterHintsWidget).
- **Буфер обмена**: copy/cut/paste внутри редактора и между редактором и 1С — через in-memory
  полифилл `navigator.clipboard`; вставка не пустая, `editor.create()` не падает.
- **Отмена операций Monaco** (`Canceled`) не всплывает ошибкой в форму 1С.
- **Старые платформы**: ниже замеренной минимальной версии редактор честно не заводится —
  зафиксировать поведение (белый экран/ошибка) для документации.

### 3.3. Ошибки

- Строковый патч Monaco не наложился (дрейф версии) → **сборка падает** (assertApplied).
- Бандл содержит синтаксис выше ES-floor → **CI падает** (es-check).

## 4. Контракты

### 4.1. Экспортные функции моста (`window` / `defaultView`) — БЕЗ ИЗМЕНЕНИЙ

Все ~150 экспортных функций (`init`, `setText/updateText/setContent/getText/eraseText`,
`setSelection/getSelection`, `setTheme/setLanguageMode/setReadOnly`, `updateMetadata/clearMetadata`,
`compare/nextDiff/previousDiff`, `getQuery`, `revealDefinition`, `insertSnippet`,
`enableQuickSuggestions`, `minimap`, `editor.trigger(...)` и остальные из README «Функции для
взаимодействия с 1С») сохраняют имена, сигнатуры и семантику. ESM-сборка 0.55 не определяет
глобальный `monaco` → в `editor.js` он публикуется явно (`MonacoEnvironment.globalAPI` +
`window.monaco`), т.к. `bsl_helper.js`/`finder.js` используют его как глобал.

Допустимые **дополнения** (не изменения): новые функции по образцу И4 (например,
`showAllUnchangedRegions`/`collapseAllUnchangedRegions`) — только по согласованию с автором.

### 4.2. События (`EVENT_*`) / формат обмена — БЕЗ ИЗМЕНЕНИЙ

Набор событий, формат `eventData1C = {event, params}` и механизм `#event-button` сохраняются.

### 4.3. Контракт сборки / доставки

| Параметр | Значение |
| --- | --- |
| Monaco | 0.55.1 (ESM, per-module; alias на `esm/vs/editor/editor.main.js`) |
| Тулчейн | webpack 5, esbuild-loader (Monaco → es2015), babel (наш код), terser `ecma:2015, quote_keys, ascii_only` |
| ES-floor | Синтаксис бандла ≤ ES2015; рантайм-API закрыты полифиллами (analysis.md §2.2); гейт `es-check es2015` на `dist/*.js` |
| Целевая платформа 1С | Ожидаемо 8.3.14+, рекомендация 8.3.18+ (по VAEditor); фактическую границу фиксирует этап 5 |
| Воркер | Blob-URL, single-chunk (`asyncChunks:false`), со своим слоем полифиллов |
| Локализация | ru; официальный `nls.messages.ru.js` ESM-путь, фолбэк — NLS-шим по схеме VAEditor |
| Строковые патчи Monaco | Только через replace-strings с `assertApplied` (перечень — analysis.md §2.4); глобальную обёртку RegExp не делать |
| Single-file | Таргет `build:single` переносится на новый стек тем же контрактом, что в [`specs/single-file-build`](../single-file-build/spec.md) §4.3 (ровно один `index.html`, ноль внешних ссылок) |
| Автотесты | Пирамида T0–T4 (analysis.md §4.3): сборочные гейты + браузерные mocha headless (`npm run test:headless`, нон-зеро exit при failures) — локально и в CI; те же тесты в реальном поле 1С (`/C autotest` → `success.txt`) — на локальном стенде. Существующие 123 кейса — базовый регресс-набор, сокращать нельзя |
| Атрибуция | Заимствования из VAEditor — с указанием источника и лицензии BSD-2 |

## 5. Критерии приёмки (спайк удался)

- [ ] Этап 1: «голый» Monaco 0.55.1 открывается и печатает в поле 1С на Windows (базовое доказательство).
- [ ] Функциональный паритет по чек-листу: подсветка BSL/запросов/СКД, автодополнение (вкл.
      метаданные), hover, подсказки параметров, переход к определению, фолдинг (вкл. запросы и
      `#Область`), сниппеты, форматирование, темы (6 шт.), режим сравнения (side-by-side и inline,
      навигация по диффам, счётчик), закладки/брейкпоинты, маркеры ошибок, статусбар, дерево
      переменных, контекстное меню, поиск.
- [ ] Мост: все экспортные функции на `window` живы (DevTools), события `EVENT_*` доходят до 1С.
- [ ] Копипаста работает в поле 1С (не пустая вставка), `Canceled` не всплывает в форму.
- [ ] `es-check es2015` зелёный; assertApplied патчей зелёный.
- [ ] Браузерные mocha-тесты (123 существующих + новые кейсы под точки дрейфа) зелёные в
      headless-прогоне (`npm run test:headless`).
- [ ] Те же тесты зелёные **внутри реального поля 1С** (запуск `/C autotest`, механика
      VAEditor: `mochaResults` → `success.txt`) на Windows-стенде.
- [ ] Windows-гейт: 1С 8.3.27+ с включённой «Защитой от опасных действий».
- [ ] Зафиксирована минимальная версия платформы 1С, на которой редактор работает.
- [ ] Наблюдения macOS (клавиатура!) и Linux задокументированы (даже если «не работает» — это результат).
- [ ] Single-file-таргет собирается на новом стеке и проходит смоук zero-external.
- [ ] Итоговый отчёт: объём изменений, компромисс по платформам, рекомендация.

## 6. Вне области

- **Мерж** — по итогам спайка и отдельному решению; спайк не оформляется PR автоматически.
- **Изменение публичного контракта** моста/событий (новые функции — только как дополнения по согласованию).
- **Редизайн обвязки** (переписывание bsl_helper, отказ от MutationObserver-хаков как класса) —
  только точечная миграция; архитектурные улучшения — отдельно.
- **Новые фичи Monaco 0.5x** (inline completions, semantic tokens, LSP) — не включать; максимум
  зафиксировать возможности в отчёте.
- **Гарантированный фикс macOS** — цель «проверить и задокументировать», не «обязательно починить».
- **Поддержка платформ ниже замеренной границы** (совместимость со старым WebKit ниже ~Safari 11 /
  IE-эпохи) — сознательно теряется, это и есть предмет решения автора.
- Ветка `webpack-monaco-v0.47.0` — используется только как референс, не дорабатывается.
