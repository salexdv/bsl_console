# custom-suggestions-codicon: специальные пользовательские подсказки и Codicon

> Issue: #368

## 1. Контекст и проблема

Публичная функция `showCustomSuggestions` умеет показывать только обычные пункты, которые вставляют
текст. Вызывающему коду 1С также нужны командные пункты: они должны визуально отличаться, иметь
настраиваемую иконку Codicon и вместо вставки текста отправлять заданное событие.

## 2. Область изменений

| Компонент | Тип | Характер изменений |
| --- | --- | --- |
| `src/editor.js` | обвязка редактора / мост 1С | расширение `showCustomSuggestions`, обработка выбора |
| `src/decorations.css` | интерфейс | оформление специальных пунктов |
| `docs/` | документация | описание контракта и актуальных Codicon |

## 3. Поведение

### 3.1. Основной сценарий

1. Обычная пользовательская подсказка продолжает вставлять `text`.
2. Поле `codicon` заменяет стандартную иконку пункта указанным CSS-классом Codicon.
3. Если заполнено поле `event`, пункт считается специальным: текст не вставляется, список закрывается,
   а в 1С отправляется событие с именем из `event`.
4. Специальный пункт без `codicon` получает `codicon-symbol-event`.
5. Выбор специального пункта одинаково работает мышью, Enter, Tab и символом из
   `activeSuggestionAcceptors`; после события фокус возвращается редактору.

### 3.2. Граничные случаи

- `codicon` разрешён и для обычного пункта.
- `showPreviousCustomSuggestions` повторно показывает пункты вместе с `event` и `codicon`.
- Нулевой диапазон специального пункта фиксируется в позиции курсора, поэтому Monaco не заменяет
  текущее слово.

### 3.3. Ошибки

- Некорректный JSON возвращает `{ errorDescription: <текст ошибки> }`, как и раньше.
- Неизвестный CSS-класс Codicon передаётся без дополнительной валидации.

## 4. Контракты

### 4.1. Экспортные функции моста (`window` / `defaultView`)

```js
/**
 * Показывает пользовательские подсказки.
 * @param {string} suggestions JSON-строка с описаниями пунктов.
 * @returns {true|{errorDescription: string}} Результат разбора и показа.
 */
window.showCustomSuggestions(suggestions)
```

Дополнительные поля элемента JSON:

| Поле | Тип | Описание |
| --- | --- | --- |
| `event` | `string` | Имя события вместо вставки текста |
| `codicon` | `string` | CSS-класс `codicon-*` |

### 4.2. События (`EVENT_*`) / формат обмена с 1С

Имя события задаётся вызывающим кодом в поле `event`; новая фиксированная константа `EVENT_*` не
добавляется.

```json
{
  "current_word": "",
  "last_word": "авансовыйотчет",
  "last_expression": "документы.авансовыйотчет.",
  "position": {
    "lineNumber": 17,
    "column": 54
  }
}
```

### 4.3. Контракт сборки / доставки

Используется Codicon-шрифт Monaco 0.55.1, который уже инлайнится webpack-конфигурацией. Новых внешних
ассетов нет. Функция остаётся доступна как `window.showCustomSuggestions`.

## 5. Критерии приёмки

- [ ] Обычный пункт без новых полей работает как раньше.
- [ ] `codicon` отображается у обычного и специального пункта.
- [ ] Специальный пункт без `codicon` показывает `codicon-symbol-event`.
- [ ] Выбор специального пункта не меняет текст и ровно один раз отправляет заданное событие.
- [ ] Payload события содержит `current_word`, `last_word`, `last_expression`, `position`.
- [ ] Мышь, Enter, Tab и пользовательский символ выбора поддержаны.
- [ ] `showPreviousCustomSuggestions` сохраняет новые свойства.
- [ ] Тестовая, production- и single-file-сборки проходят.
