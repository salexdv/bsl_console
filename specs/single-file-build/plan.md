# single-file-build: план реализации и решения

Транзиентный спутник [`spec.md`](spec.md). Этапы, открытые вопросы, журнал решений.

## 1. План реализации

### Этап 0. Согласование и база (текущий)

- Шаги: спека → согласование; сверить тайминг конвергенции веток (#368 и др. вливаются в обе ветки
  со сходимостью на `webpack` — диф должен лечь после/вместе, не конфликтуя).
- Gate: `status: approved` в spec.md. Решение по таймингу: ждём конвергенцию или идём сейчас и ребейзим
  (диф крошечный, ребейз дешёвый).
- Оценка: 0.5 дня (без учёта ожидания ответа автора).

### Этап 1. Single-file таргет в webpack.config.js

- Шаги:
  1. Ветка `feature/single-file-html` от `origin/webpack`.
  2. `npm install`, контрольная обычная сборка `npm run build` — зафиксировать состав `dist/`
     (бейзлайн для проверки «регресса нет»).
  3. В `webpack.config.js` принять `env.single` (webpack4/webpack-cli3: `--env.single`; проверить
     фактический синтаксис CLI v3 — `env` приходит первым аргументом функции конфига).
  4. При `single`: `LimitChunkCountPlugin({maxChunks:1})`, `splitChunks: false` (не плодить то, что
     потом мержить), `url-loader` без лимита, убрать `CopyWebpackPlugin`.
  5. `package.json`: `"build:single": "webpack --mode production --env.single --progress"`.
- Gate: `dist/` после `build:single` = один `index.html`; обычный `build` даёт бейзлайн-состав.
- Оценка: 0.5–1 день (включая возню с webpack4-нюансами).

### Этап 2. Инлайн иконок дерева (Г2)

- Шаги:
  1. `editor.js`: собрать карту `require.context('./tree/icons', false, /\.png$/)` → `{имя: dataURI}`,
     передать в `new Treeview(...)` резолвер-функцию вместо строки `"./tree/icons/"`.
  2. `tree.js`: в месте `src = imageBase + icon` — `typeof imageBase === 'function' ?
     imageBase(icon) : imageBase + icon` (одна строка; обратная совместимость со строкой).
  3. Проверить `tree.css` url(`./icons/...`) — инлайнятся через css-loader→url-loader (все < 8 КБ).
- Gate: в dev-странице (`npm run debug` → test) дерево переменных показывает иконки; в single-сборке
  нет ссылок `tree/icons/*`.
- Оценка: 0.5 дня.
- Примечание (ребейз-устойчивость): `tree.js` на `develop` переписан (−222 строки) и приедет на
  `webpack` при конвергенции; там та же точка `this.imageBase + this.getIconName(item)` (tree.js:117) —
  правка переносится 1-в-1.

### Этап 3. Смоук-проверка zero-external

- Шаги: node-скрипт без зависимостей (напр. `tools/check_single.js`): (а) `dist/` содержит ровно
  `index.html`; (б) в html нет `src=`/`href=`/`url(...)`, не начинающихся с `data:`/`blob:`/`#`/`about:`
  (инлайн-атрибуты `<script>`/`<style>` без src — ок); нон-зеро exit + перечень нарушений.
  npm-скрипт `check:single`; вызывать в конце `build:single` (через `&&`) и в CI.
- Gate: скрипт зелёный на single-сборке, красный при искусственно подложенном внешнем файле.
- Оценка: 0.5 дня.

### Этап 4. Ручная верификация (главный гейт)

- Шаги:
  1. Браузер: открыть `dist/index.html` с диска, DevTools → Network: ноль файловых запросов;
     Console → `window.init`, `window.setText`, `window.editor` определены; прогнать основные
     сценарии (текст, подсветка BSL/запросов, автодополнение, темы, compare).
  2. 1С 8.3.27+ (Windows, «Защита от опасных действий» ВКЛ): загрузить html **текстом** в
     ПолеHTMLДокумента; предупреждения нет; мост живой (init/setText/getText/события через
     `#event-button`).
  3. По возможности — Linux-контейнер (снять картину; ветка webpack = Linux-сборка автора, ожидаемо ок).
- Gate: критерии приёмки §5 spec.md (кроме Action) закрыты.
- Оценка: 0.5–1 день (зависит от доступности стенда 1С 8.3.27).

### Этап 5. GitHub Action + доки + PR

- Шаги:
  1. `.github/workflows/release-single.yml`: on release (published) → `npm ci && npm run build:single`
     → приложить `dist/index.html` как `bsl_console.single.html` в Release assets. (Workflows в репо
     нет — файл новый; CI-токену нужен scope `workflow`.)
  2. README (+CHANGELOG, если ведётся): раздел про single-file — зачем (8.3.27+), как собрать, как
     загрузить в поле текстом.
  3. Прогнать Action (тестовый tag/release), убедиться в артефакте.
  4. PR: узкий диф (config + 2 строки src + скрипт + workflow + доки), ссылка на issue #18.
- Gate: зелёный Action; PR открыт, мейнтейнер в курсе.
- Оценка: 0.5–1 день.

### Риски и снижение

| Риск | Снижение |
| --- | --- |
| Конвергенция автора (develop→webpack, #368) конфликтует с нашим дифом | Диф микроскопический; правка tree.js переносится 1-в-1 на новый tree.js (та же точка концата). Согласовать тайминг, быть готовым к ребейзу. |
| `ScriptExtHtmlWebpackPlugin.inline:['console.js']` не заматчит после `maxChunks=1` | Матч по имени entry-чанка — он остаётся `console.js`. Проверяется на Этапе 1 по факту. |
| `base64-inline-loader` `limit` — no-op, шрифт мог бы эмититься файлом | По докам лоадер инлайнит всегда (limit игнорируется) — это нам на руку; верифицируем грепом по dist (Этап 3 ловит автоматически). |
| Размер html вырастет (весь Monaco + base64) до ~5–10 МБ — поле 1С грузит его строкой | Пределов на длину строки в 1С практически нет; замерить фактический размер и время загрузки на Этапе 4. Минификация уже включена (production). |
| Старый WebKit поля не съест что-то из инлайна (например, огромный data:-URI) | ES-floor не трогаем (транспиляция та же); data:-URI шрифтов уже в проде ветки. Гейт — ручной тест 8.3.27 (Этап 4). |
| webpack4 `--env.single` синтаксис/поведение (webpack-cli 3) | Проверить на Этапе 1; запасной вариант — отдельный `webpack.single.config.js`, наследующий основной (чуть больше файлов, но проще CLI). |

## 3. Решения

| Дата | Решение | Причина |
| --- | --- | --- |
| 2026-07-12 | База — `origin/webpack`, не `develop` и не `webpack-monaco-v0.47.0` | Прямое указание автора; webpack-ветка уже инлайнит бандл/шрифты/воркер |
| 2026-07-12 | Отдельный таргет `build:single`, а не изменение обычного `build` | Не ломать текущих потребителей обычной сборки; минимальный ревьюибельный диф |
| 2026-07-12 | Иконки дерева — через `require.context`-карту в `editor.js` + резолвер в `Treeview`, а не копирование/строковые патчи | Рантайм-концат `imageBase+icon` webpack не видит (потому и CopyWebpackPlugin); правка в 1 строку, обратно совместима со строковым `imageBase` (standalone tree.html), переносится на новый tree.js с develop |
| 2026-07-12 | В single-режиме дополнительно `splitChunks:false` (а не только maxChunks=1) | Нет смысла резать чанки, чтобы потом их мержить; меньше сюрпризов порядка исполнения |
| 2026-07-12 | Смоук — самописный node-скрипт без новых devDependencies | Не раздувать package.json ради грепа; переносимо (Win/Linux/CI) |
| 2026-07-12 | `loading.gif` (41 КБ, > лимита url-loader) закрываем снятием лимита, а не выпиливанием | На develop от него уже отказались (c992ecf) — выпиливание приедет конвергенцией; снятие лимита — гарантия «ноль внешних» независимо от контента |
| 2026-07-12 | Спека согласована; код пишем сразу, конвергенцию веток не ждём | Диф крошечный, ребейз дешёвый; блокировка на недели не оправдана |
| 2026-07-12 | Копирование `tree/icons` в обычной сборке оставляем как есть | Минимальный диф; вопрос «убрать совсем?» задать автору перед PR |
| 2026-07-12 | GitHub Action — через `gh release upload` (gh CLI предустановлен), без сторонних actions | Меньше зависимостей и доверия для ревью; `npm install` (не `ci`) — в репо нет lock-файла |

## 4. Журнал верификации

- **Этап 1–3 (2026-07-12):** `npm run build:single` → `dist/` = ровно один `index.html` (7.51 МБ),
  `check:single` зелёный. Регресс: `npm run build` байт-в-байт совпал с бейзлайном (40 файлов).
- **Инлайн (греп по single-html):** 35× `data:image/png` (иконки), 1× `data:image/gif` (loading.gif),
  21× `data:image/svg`, шрифт `data:font/ttf`, воркер через `createObjectURL` (blob). Ссылок на
  `tree/icons/*` и файловый `editor.worker.js` — нет (`editor.worker.js` встречается лишь как лейбл
  внутри `MonacoEnvironment`, не URL).
- **Этап 4 браузер (2026-07-12):** стенд `test-harness.html` (iframe +
  вызовы `contentWindow.*` = имитация `defaultView` 1С). Network показал только два html-документа +
  `data:`/`blob:` — **ноль внешних файлов**. Мост на `window` полный. Печать, подсветка BSL/запросов,
  автодополнение (`updateMetadata` → `Справочники.`), темы (vs/vs-dark), `compare` — работают.
- **Этап 4 гейт 1С 8.3.27+ (Windows, «Защита от опасных действий» ВКЛ) — ПРОЙДЕН (2026-07-12):**
  собрана тестовая `console-single.epf` (макет `single` = ДвоичныеДанные + `HTML = ПолучитьСтроку…`
  вместо `file://`; разбор/сборка через `Dump/LoadExternalDataProcessorOrReportToFiles`). В 1С 8.3.27.2214
  с включённой защитой: **предупреждения «открыть локальный файл» НЕТ**, редактор работает (в т.ч.
  blob-воркер и data:-ассеты в поле 1С). Замысел подтверждён end-to-end.
- **Открытый минус (2026-07-12):** время загрузки страницы заметно выросло (весь Monaco + ассеты
  инлайном в одном 7.9 МБ HTML, парсится синхронно; старый путь грузил вендор-чанки отдельными файлами
  + кэшировал распакованное на диске). Автор снимает замер, что именно долго. См. открытый вопрос №5.
