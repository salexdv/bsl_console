# query-descriptions: примечания подзапросов в режиме запроса

Стабильный контракт: что должно быть реализовано и как вызывающий код/пользователь это видит.
Переживает merge, уезжает в `specs/done/query-descriptions/spec.md`. Транзиентное (этапы, вопросы,
решения) — в [plan.md](plan.md).

## 1. Контекст и проблема

Консоль запросов показывает пакет из нескольких подзапросов, разделённых строками с одним `;`.
1С знает назначение каждого подзапроса (остатки, продажи, итоги), редактор — нет. Нужна функция,
по которой 1С передаёт массив примечаний, а редактор выводит их серым текстом у правого края
строки: примечание подзапроса `i` — на строке разделителя `i`, примечание последнего подзапроса —
на последней строке запроса.

Определение подзапросов — как у опции `renderQueryDelimiters` (`getQueryDelimiterDecorations`,
`src/editor.js`): строки, целиком состоящие из `;` с окружающими пробелами (`^\s*;\s*$`).

## 3. Поведение

### 3.1. Основной сценарий

1. Режим редактора — `bsl_query` или `dcs_query`. 1С вызывает `setQueryDescription(descriptions)`
   с массивом строк (или JSON-строкой с ним). Индекс элемента равен индексу подзапроса (с нуля).
2. Редактор ищет в тексте модели разделители `^\s*;\s*$` (сортировка по строкам) — их количество
   `N`. Примечание с индексом `i < N` выводится на строке разделителя `i`. Примечание с индексом
   `N` — на последней непустой строке модели, но только если после последнего разделителя есть
   текст запроса (последняя непустая строка не является строкой последнего разделителя).
3. Примечание — серый однострочный текст в крайней правой позиции строки (правый край области
   кода, до минимальной карты, если она включена). Если контент шире видимой области — правый край
   прокручиваемого контента (подпись видна при горизонтальной прокрутке до конца).
4. При каждом изменении текста модели якоря пересчитываются автоматически: подпись следует за
   своим разделителем, при удалении разделителя индексы сдвигаются.
5. Ввод не зависит от опции `renderQueryDelimiters`: подписи рисуются всегда в режимах запроса,
   опция управляет только подсветкой разделителей.

### 3.2. Граничные случаи

- Пустая строка в массиве — подзапрос без подписи (индекс при этом не сдвигается).
- Элементы с индексами за пределами числа подзапросов (в т.ч. когда текст кончается на `;` и
  подписи с индексом `N` некуда ставить) — молча игнорируются.
- Разделители внутри строковых литералов и комментариев не отличают от прочих — поиск по всему
  тексту модели, как у `renderQueryDelimiters`.
- Очистка набора: пустой массив или `null` (возврат `true`); `setLanguageMode` в режим, отличный
  от режимов запроса, — набор забывается, подписи убираются; полная замена текста модели —
  набор забывается.
- `setText`/`setContent` с тем же текстом (побайтово) — не полная замена, набор сохраняется.
- Режим сравнения (`compare`) и вкладки: как у `setQueryParamsTooltips` — в compare `false`;
  набор хранится на редакторе вкладки, изоляция вкладок автоматическая.
- Переключение темы — цвет подписи следует теме (серый для светлой/тёмной).
- Подписи не кликабельные (`pointer-events: none`), событий не генерируют.
- Сосуществование с `setQueryParamsTooltips`/`setInlayHints` — независимые механизмы: подписи
  рисуются собственными декорациями и набор инлей-хинтов не занимают.

### 3.3. Ошибки

- Невалидная JSON-строка или не-массив (кроме `null`) — `{ errorDescription }`, предыдущий набор
  не меняется.
- Вызов до инициализации редактора, в режиме сравнения или вне режимов запроса — `false`.

## 4. Контракты

### 4.1. Экспортные функции моста (`window` / `defaultView`)

```js
/**
 * Показывает примечания подзапросов в режимах bsl_query / dcs_query: серый текст у правого
 * края строки разделителя ; (или последней строки запроса для последнего подзапроса).
 * Индекс элемента массива равен индексу подзапроса (подзапросы определяются по строкам-разделителям,
 * см. опцию renderQueryDelimiters). Якоря пересчитываются при каждом изменении текста.
 * @param {string|string[]|null} descriptions массив примечаний, JSON-строка с ним или null
 *   (очистка); пустая строка — подзапрос без подписи.
 * @returns {boolean|{errorDescription: string}} true — набор принят (пустой массив/null —
 *   очищен); false — редактор недоступен, режим сравнения или не режим запроса;
 *   {errorDescription} — ошибка разбора.
 */
function setQueryDescription(descriptions) { ... }
```

### 4.2. События (`EVENT_*`) / формат обмена с 1С

Новых событий нет: подписи некликабельные, только отображение.

### 4.3. Контракт сборки / доставки

- Используется только стабильное API Monaco 0.55.1 (`model.findMatches`, `deltaDecorations`,
  whole-line `className`, `zIndex` декораций).
- Итоговый JavaScript — ES2018 (проверка `npm run escheck`), без новых внешних ассетов —
  single-file-сборка (`build:single`, `build:pack`) не меняется. Новых воркеров и чанков нет.

## 5. Критерии приёмки

- [ ] `setQueryDescription([...])` в `bsl_query`/`dcs_query` рисует серую подпись у правого края
      строки каждого разделителя `;`, последнюю — у последней строки запроса (`npm run debug`,
      обе темы, с минимальной картой и без неё).
- [ ] Вставка строки выше разделителя смещает подпись вместе с ним; удаление разделителя
      сдвигает индексы последующих подписей — без повторного вызова из 1С.
- [ ] Вызов в режиме `bsl` возвращает `false`; `setLanguageMode('bsl')` очищает подписи.
- [ ] Пустой массив/`null` очищает подписи; невалидный вход — `{errorDescription}` без смены
      предыдущего набора.
- [ ] Подписи работают в `dcs_query` и независимо от опции `renderQueryDelimiters`.
- [ ] Гейты: `npm run test`, `build:test` + `test:mocha`, `escheck`, `build`.

## 6. Вне области

- Различение разделителей в строках/комментариях, привязка к объектной модели запроса
  (`src/query_model.js`).
- Отдельная функция `clearQueryDescription` — очистка через `setQueryDescription([])` / `null`.
- Клик по подписи и события; многострочные подписи.
- Автогенерация примечаний из текста запроса (1С передаёт список целиком).
