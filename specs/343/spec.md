# 343: Пользовательские подсказки параметров для контекстных вызовов

> Issue: https://github.com/salexdv/bsl_console/issues/343

## 1. Контекст и проблема

После перехода к определению полного выражения вызова `setCustomSignatures` перестала находить
короткие ключи для методов после точки: ключ `добавить` не совпадал с выражением
`я.колонки.добавить`. Событие `EVENT_BEFORE_SIGNATURE` при этом продолжало передавать короткое поле
`word`. Разрешение подсказок внутри строк было восстановлено безусловным отключением проверки
строкового литерала, из-за чего скобки внутри строки могли восприниматься как вызов.

## 2. Область изменений

| Компонент | Тип | Характер изменений |
| --- | --- | --- |
| Контекст подсказки параметров | src | токен-aware поиск активного вызова |
| `setCustomSignatures` | мост 1С | совместимый поиск по полному и короткому ключу |
| `EVENT_BEFORE_SIGNATURE` | мост 1С | добавление полного выражения вызова |
| Документация и браузерные тесты | docs / test | фиксация и проверка контракта |

## 3. Поведение

### 3.1. Основной сценарий

1. Редактор определяет активную открывающую скобку вызова с учётом вложенности и токенов языка.
2. Из выражения слева от скобки формируются полное имя и последнее, короткое имя метода.
3. Пользовательская сигнатура сначала ищется по полному имени, затем по короткому.
4. Событие передаёт оба имени вызывающему коду 1С.

### 3.2. Граничные случаи

- Регистр ключа не влияет на поиск.
- Полный ключ имеет приоритет над коротким.
- Скобки и запятые в строках и комментариях не участвуют в разборе вызова.
- Курсор внутри строкового аргумента относится к внешнему вызову.
- В обычном режиме BSL содержимое встроенного запроса не считается вызовом BSL.
- В режимах запроса и СКД функции языка запроса продолжают распознаваться.
- При отсутствии активного вызова имена пусты и подсказка не формируется.

## 4. Контракты

### 4.1. `setCustomSignatures`

Ключом объекта может быть короткое имя (`добавить`) или полное выражение
(`я.колонки.добавить`). Сопоставление регистронезависимое. При наличии обоих ключей применяется
полный. Формат массива `SignatureInformation` и обработка невалидного JSON не меняются.

### 4.2. `EVENT_BEFORE_SIGNATURE`

| Поле | Направление | Тип | Описание |
| --- | --- | --- | --- |
| `word` | JS → 1С | `string` | Короткое имя функции или метода в нижнем регистре |
| `expression` | JS → 1С | `string` | Полное выражение вызова в нижнем регистре |

Остальные поля payload сохраняются без изменений. Добавление `expression` обратно совместимо.

## 5. Критерии приёмки

- [x] Ключ `добавить` показывает сигнатуру для `я.Колонки.Добавить(`.
- [x] Полный ключ переопределяет короткий ключ.
- [x] Подсказка внешнего вызова работает внутри строкового аргумента.
- [x] Текст `Строка = "Вызов("` не создаёт ложный вызов.
- [x] `word` и `expression` передаются в `EVENT_BEFORE_SIGNATURE` согласно контракту.
- [x] Браузерные тесты BSL, запросов и СКД проходят на Monaco 0.55.1.
- [x] Production-сборка соответствует ES2018 и сохраняет Blob-воркеры.

## 6. Вне области

- Валидация содержимого массива пользовательских сигнатур.
- Изменение формата JSON или синхронного способа вызова `setCustomSignatures`.
- Изменение Monaco Editor или минимальной версии платформы 1С.
