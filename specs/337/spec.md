# 337: Управление справочником bslGlobals через публичный API

## 1. Контекст и проблема

Потребителям редактора нужен небольшой контекст глобальных объектов для подсказок BSL.

## 2. Область изменений

| Компонент | Тип | Характер изменений |
| --- | --- | --- |
| `src/editor.js` | src | добавить публичную очистку и фильтрацию |
| `README.md`, `docs/` | доки | описать новые функции |

## 3. Поведение

`clearBslGlobals()` сохраняет корневые разделы `bslGlobals`, очищая их содержимое. Операция необратима до перезагрузки редактора.

`filterBslGlobals(paths, exclude = false)` принимает массив путей `раздел.объект` или JSON-строку с таким массивом. При `exclude = false` остаются только перечисленные объекты, при `true` перечисленные объекты исключаются. Неизвестные пути игнорируются. При некорректном JSON или значении не-массиве функция возвращает `false` без изменения справочника. Каждый успешный вызов изменяет текущий справочник; удалённые объекты нельзя восстановить до перезагрузки редактора.

## 4. Контракты

### 4.1. Экспортные функции моста

```js
clearBslGlobals(): boolean
filterBslGlobals(paths: string[] | string, exclude?: boolean): boolean
```

## 5. Критерии приёмки

- [ ] Обе функции доступны через `window`.
- [ ] После очистки корневые разделы существуют и пусты.
- [ ] Поддержаны режимы включения и исключения выбранных объектов.
- [ ] Повторная фильтрация применяется к текущему результату и не восстанавливает удалённые объекты.
- [ ] Функции описаны в README и отдельных документах.

## 6. Вне области

- Фильтрация вложенных методов и свойств отдельными путями.
- Изменение `bslMetadata`, `bslQuery`, `bslDCS` и пользовательских функций.
